# 物理引擎只用於實體驗證，模型仍是運動學連動

模型把平面插圖立體化後，出現零件干涉、憑空連動（深度方向的軸或銷沒補上）、靠接觸的動作與原文不符等問題，讀者會因此誤解機構。為了有系統地找出這些問題，引入一個 3D 物理引擎，但只給維護者的實體驗證使用：它是開發用依賴，網站不載入，`npm test` 也不需要它。模型本身仍照 ADR-0001 由幾何關係算出姿勢。

實體驗證分三項。干涉與憑空連動對全書每個模型檢查，做法是把模型算出的姿勢擺進引擎做碰撞偵測，不模擬力。動力重演只做靠接觸或重力運作的機構（棘爪、凸輪、擒縱、落錘等）：只推主動件，其餘由碰撞、樞軸與重力帶動，再和模型比動作的順序與停下的位置。

## Considered Options

- **全書都做動力重演**：最接近「真的驗證」，但齒輪嚙合與皮帶在物理引擎裡會打滑、卡住、抖動（ADR-0001 的原因仍成立），會產生大量誤報，而且每個模型都要另外宣告關節。
- **只做干涉檢查**：抓不到憑空連動，也無法驗證落下、彈回這類動作成不成立。
- **不加依賴、自己寫碰撞與動力**：等於自己寫一個小物理引擎，其正確性又要另外驗證。

## Consequences

- 動力重演不比快慢：原書沒有重量與彈簧力的資料，落下、彈回的時間仍由模型定義指定。
- 干涉檢查會報出無害的重疊（軸在沒畫出的孔裡、簡化的機架）；這些以豁免處理，寫在模型定義裡並註明原因。
- 實體驗證只回答「實物做不做得到」。是否符合原文、是否認得出是插圖上的機構，仍要人對照；三者衝突時原文優先於實物可行，實物可行優先於插圖外形。
- 改動或新增模型後要另外跑實體驗證，它不在 `npm test` 裡。
