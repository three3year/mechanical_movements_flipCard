## Testing Decisions

- **接縫**:沿用現有的兩個——模型定義(`npm test`,對各圖匯出的 pose() 與接觸函式下斷言)與實體驗證(`npm run verify`)。工具的改動用各自的測試先寫失敗的例子:`rigid-links.mjs` 與外形檢查的測試、實體驗證的兩點旋轉剖面用 `npm run test:verify`。不新增接縫;截圖對照照 `docs/agents/model-audit.md` 的做法手動做。
- **好的斷言**:對到原文的一句(例:「一次只作用於一個蝸輪」「重量越大咬得越緊」「在河床處打開一條通道」),或對到接觸(相碰的一對間隙接近 0、少轉一點就穿入、全程不穿入),或對到守恆(桿長、繩長不變),或對到方向(接觸點的切線速度和材料同向)。不要只數零件的塊數或重複模型自己的公式;這次掃描抓到測試鎖住錯誤行為的例子(第 401 種以頂部當死點、第 418 種「弧心在銷上」、第 436 種把「略呈切線」對到斜置角度、第 469 種轉速比、第 483 種沒驗進氣時機、第 488、496 種沒驗方向、第 499 種只驗轉角單調)。
- **每筆先寫失敗的測試再改模型**(TDD),能用斷言表達的都要有斷言;純外觀的(箭頭位置、字母、顏色、取景、遮擋)以截圖確認並寫進報告。
- **前例**:第 388 種「兩個滾子在接觸處和木板同向同速」;第 390 種皮帶長度不變、不打滑;第 391 種「咬著的那一面貼著齒、少轉一點就穿入」;第 287 種進程型與節流閥;第 502 種補的副軸與夾塊。
