# 複查逐圖表格:螺旋機構(第 102–112 種)

票:[02-screws](../issues/02-screws.md)。規則見[規格](../spec.md)的「回饋規則」;用語見 `CONTEXT.md`(由接觸算、演出的動作、主動件、目標件、動力重演)。格式照 `01-crank-cam.md`。

## 這一族的總結

- 11 張都查過四項。有修的 9 張,沒有問題的 2 張(第 110、112 種)。
- **主動件換了零件**:無。**目標件換了零件**:第 102 種拿掉目標件(原本標在不動的螺栓上;見下方)。
- **第 35–85 種外觀受影響**:無。共用模組的改動:`models/supports.js` 新增 `pedestalX`(軸沿 x 的軸承座),`models/groove-cam-pair.js`(只有第 106、107 種用)改了溝的取樣與銷的形狀;都不影響第 1–85 種。
- 「未修」豁免:這一族原本 0 項,現在 0 項。第 108 種一項干涉豁免(尖點擦到交會處的凸條)因為交會處改成切通而移除。
- 動力重演:新增宣告 3 張:第 106、107 種通過;第 108 種寫了具體原因的豁免(尖點要靠慣性衝過交會處,重演不比快慢,見表)。不適用 8 張:螺帽整圈套在螺紋上(第 102、103、105、109、111、112 種)、半螺帽扣在螺紋上(第 110 種)——螺紋兩側都夾著它,是套住的接合;第 104 種是蝸桿與蝸輪的嚙合。第 99 種(上一族)的銷原本只擱在凸條上、沒咬住,所以要重演確認;這一族的螺帽本來就咬在螺紋裡。
- 瞬移掃描(`node tools/scan-models.mjs 60 102 … 154`,四族一起掃):沒有報出;「沒有目標件」只列出第 102、134 種(都在不標目標件的例外清單)。
- 檢查點:這一族的測試檔全過;`npm test` 全書 527 項中 5 項失敗,都是其他族正在改的(第 293、299、370 種與接頭章),不是這一族的圖。`npm run verify -- 102-112` 通過(0 個未豁免的問題)。共用模組只新增函式(`supports.js` 的 `pedestalX`、`cams.js` 的 `outlineArc`),沒改既有函式,其他圖不受影響,所以沒有重跑全書的實體驗證。插圖並排截圖每張至少一個相位。
