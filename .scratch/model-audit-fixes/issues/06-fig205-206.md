### 2026-10-11 完成

**做了什麼**

- 第 205 種(#205-1):輪維持等速(一圈兩格,`wheelAngle` 與舊測試不變)。兩個凸輪的外形在模型載入時由齒反求:小齒輪轉一圈、輪照等速轉,把那一組齒換到小齒輪的座標裡,沿每個方向量齒最靠近軸心的地方(最遠到尖端 0.85),凸輪就是齒從沒掃到的那一塊。得到的是心形凸輪(和 507movements 動畫的凸輪外形相近):大半圈頂著自己那組齒的側面推,背面同心的一段只擦過齒端,交接時兩個一起推。齒改成兩組外端都在 2.55(長齒內端 1.6、短齒 1.85),厚度從輪板面起算,接到輪板上(上面那一筆一起修了,`node tools/one-piece.mjs 205` 不再報)。匯出 `contactAt(alpha, lag)` 給測試。載入約 0.4 秒。
- 第 205 種(#205-2):小齒輪的箭頭半徑 1.0、`spinOffset` 0.5,在前面凸輪與長齒的前方;截圖確認看得到、朝逆時針。
- 第 206 種(#206-1):推動改成「頂在陡面上就一直推」:沒在推的爪往順時針頂進陡面(陡面裡貼著它的一條)的那一步起,推的那一角跟著棘輪轉、離掛銷的距離不變,每一步由兩圓交點解出棘輪轉到哪,掛銷往回走(要讓棘輪倒轉)才放開;沒在推的爪照舊靠自重落、沿齒背滑。拿掉 `FACES` 與「推到不重疊」。爪尖改成鉤形(推的那一面沿半徑、背面比斜背陡)。
- 測試(`tests/mangles.test.js`,放在各圖既有測試旁邊):「第 205 種:兩個凸輪與兩組齒相互嚙合——各自貼著自己那組齒、不穿入,任何時刻至少一個凸輪推著齒,交接時兩個一起推」(推 = 讓輪少轉 0.02 弧度就穿進齒裡;推的那一個間隙 < 0.005);「第 206 種:「一個在上升時嚙合」——…棘輪每格轉角不超過下降一程平均的 2 倍」(播放一格 = 一程的 1/36;另查上升那一程三分之二以上的格在走)。兩個都先看它失敗(205:小齒輪轉 0 時沒有凸輪推著齒;206:主動量 0.157 那一格是下降一程平均的 7.8 倍)。
- 第 206 種的動力重演:第一個來回現在和模型一致,`at: 2 * SWING` 的豁免拿掉;第二個來回少推約一齒(−26°,模型 −36°),豁免改寫原因。
- 驗證:`npm run verify -- 205-206` 0 個未豁免、1 項豁免;`npm test` 2738 項全過;`node tools/rigid-links.mjs 205 206`、`node tools/one-piece.mjs 205 206` 都是 0 張。截圖:205 v=0、1.2、3.2、4.8 與斜後方 0、1.6,放大小齒輪 0.6–4.2;206 v=0.15、0.45、0.75、1.05 與斜後方 0.3、0.9,放大兩個爪。

**和票不同的地方**

- 第 206 種只改推動的算法不夠:原本的槓桿軸在掛銷右上方,左爪一程只沿棘輪走 0.66–0.84 齒,而且兩爪輪流推的狀態不只一種(每一程開頭空走多少看爪往回滑後的落點),左爪會落到整程搆不到陡面的那一種。所以另外改了槓桿軸的位置(移到和掛銷差不多一樣高,原圖的槓桿本來就近乎水平)、擺幅 36° → 34°、左爪長 2.52 → 2.56、右爪拱高 0.45 → 0.3(從移下來的槓桿軸下面過)。已寫進報告「需要你決定的」第 206 種。
- 「上升那一程從頭到尾都在拉」沒有完全做到:上升、下降各推約一齒,各在一程開頭空走約三成(爪從落點走到陡面),棘輪每格轉角最多是下降一程平均的 1.7 倍。

**留下的問題**

- 第 206 種的穩定狀態對爪長很敏感:左爪長 2.53 以下、或擺幅 32° 以下,就落回左爪整程不拉的狀態;測試會抓到。
- 第 206 種載入時跑三個來回定週期,約 0.7 秒;第 205 種反求凸輪約 0.4 秒。
