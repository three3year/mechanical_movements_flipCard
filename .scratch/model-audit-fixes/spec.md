# 模型檢查第 07–12 族的修正(第 186–250 種)

Status: done

**來源:** 2026-10-10 用八類常見錯誤(`docs/agents/model-audit.md`)掃了第 186–250 種,報告在 `.scratch/model-audit/` 的 `07-engines-2.md` 到 `12-joints-1.md`,每一筆問題有證據、建議修法與同類要一起查的圖。同日對照 507movements.com 補強;報告裡的中譯問題已在全書中譯對照時修掉。2026-10-10 維護者對六份報告「需要你決定的」15 題全部作了決定(寫在各報告裡)。

## Problem Statement

第 186–250 種的模型實體驗證與測試都通過,但掃描查出 91 筆維護者看網頁會退回的問題:

- 零件的各塊不相連、樞軸銷懸在托架前面、立柱沒落地、導座浮在空中(第 3 類「一件」最多)。
- 說「推」「頂」「撞」的一對零件其實沒碰到,動作是演出的(第 188、190、205、211、212、214 種等)。
- 和原文或原圖不合:原圖每根軸四個扇形、模型只做兩個(第 223 種);B 有五道槽、模型做六道(第 212 種);轉向與插圖箭頭相反(第 207 種);下桿兩端接反(第 198 種)。
- 讀者看不出來:轉向箭頭被擋、記號浮在剖掉的那一半、虛線圓做成零件。
- 豁免的原因寫錯,蓋住了真的干涉(第 197、211、212、216 種)。

維護者逐圖對照原圖與模型,這些都是會被退回的錯。

## Solution

照六份報告的建議修法與維護者 2026-10-10 的決定,把 91 筆問題修掉;修不了的照實寫成豁免、原因以「未修:」開頭並列進待確認清單。修完每一筆在報告裡標「已修(日期)」、重新發布報告的鏡像。

跨圖共用的問題在共用模組裡一次修(例如曼格輪的驅動軸與導路、日內瓦擋止的範圍、擒縱輪的驅動來源),再修各圖自己的問題。另外新增一支只報告、不讓驗證失敗的維護工具,掃出「同一零件各塊不相連」,修完用它確認,以後各族掃描也能用。

## Implementation Decisions

- **範圍**:六份報告裡還沒修的 91 筆問題(第 07 族 8、第 08 族 24、第 09 族 25、第 10 族 8、第 11 族 15、第 12 族 11),照各筆的建議修法;有決定的照決定。報告裡「同類要一起查」指到範圍外的圖,只有第 36 種(#192-1 明寫一起改)納入,其餘留給各族。
- **維護者的決定(2026-10-10,記在各報告)**:第 188 種頰板在彎指前面;第 207 種補滾軸與材料;第 204 種補軸承;第 203 種重排槽的幾何;第 221 種改層次(推翻 pending.md「D 與 A 的軸只能往前伸」的一半);第 217 種維持 1:2;第 224 種只寫說明;第 226 種維持三圈並說明;第 233 種端頭改成滾子;第 239 種兩種配置各擋一向;第 242 種維持現狀;第 237 種照原圖改成彎爪;第 247 種桿下段開槽;第 244 種狀態說明寫明轉向;第 250 種補大輪。
- **待確認的兩筆**:#200-1(第 200 種的箭頭)沒有維護者決定,照建議修法做;#244-2 照決定只改說明。
- **先修共用模組**:
  - 曼格輪的小齒輪驅動(第 192–194、197 種):驅動軸拆成套管與花鍵軸兩件、固定長度、主動件顏色(#192-2、#192-3);小齒輪軸的導路與輪上真的溝(#192-1,含第 36 種)。
  - 日內瓦式擋止(第 212、215 種):範圍改由外形相碰決定,A 齒兩旁挖出槽角掃過的缺口(#212-1、#212-2、#215-1);第 212 種改五道槽(#212-3)。
  - 擒縱輪的驅動來源(第 234、238 種共用的擒縱驅動):補推斷的重錘或發條(#234-1、#238-1)。

- **推斷的零件**:補上的機架、軸承、導套、滾軸、材料、重錘、大輪等,一律在模型註解標明是推斷;偏離插圖的地方寫明理由(照「原文 > 實物可行 > 插圖外形」)。
- **由接觸算**:改成接觸的地方用現有的接觸工具(外形放置、重疊判斷、沿弧擺到相碰、推到不重疊),不手寫時間窗。落下段照舊用加速曲線。
- **豁免**:修好就拿掉不再需要的豁免;報出的仍要豁免的照實寫原因(例如第 197、211、212、216 種原本的「節曲線分段」範本原因);修不了的以「未修:」開頭並列進 `.scratch/physical-verification/pending.md`。
- **新的維護工具**:比照找伸縮桿的那支工具,新增一支掃「同一零件各塊不相連」的工具:對每個零件的各塊(含 pieces 的位置、厚度與轉角)以外接盒先篩,再以凸塊之間的實際距離判斷相連與否、分群,不和主體相連的群就報(只用外接盒會漏報環與內島之間的溝,見 `issues/01-one-piece-tool.md`);可指定圖號;只印報告,不讓 `npm run verify` 失敗,不改 ADR-0003。用法寫進 `CLAUDE.md` 的開發一節與 `docs/agents/model-audit.md` 第 3 類。
- **紀錄**:每筆修完,在報告該筆加「狀態:已修(日期):做了什麼」;逐圖表格對應的格子不改(保留掃描當時的判斷)。報告改完照 review-mirror 重新發布鏡像。
- **提交**:一張票一個提交;多個 session 共用 git 暫存區,用獨立暫存區只放自己的檔案。

## Testing Decisions

- **接縫**:沿用現有的兩個——模型定義(`npm test`,對各圖匯出的 pose() 與接觸函式下斷言)與實體驗證(`npm run verify`)。不新增接縫;截圖對照照 `docs/agents/model-audit.md` 的做法手動做。
- **好的斷言**:對到原文的一句(例:「凸弧 a–b 頂住 A 時 A 停住」「銷撞到引導片後小齒輪才轉」),或對到接觸(相碰的一對間隙接近 0、少轉一點就穿入、全程不穿入)。不要只數零件的塊數或重複模型自己的公式(這次中譯對照的 code review 退回過這兩種)。
- **每筆先寫失敗的測試再改模型**(TDD),能用斷言表達的都要有斷言;純外觀的(箭頭位置、記號、顏色)以截圖確認並寫進報告。
- **前例**:第 63 種「落板上的銷撞擊棘爪」(銷繞落板樞軸轉、落下過程貼著棘爪不穿入);第 400 種「B 靠自重坐在凸輪上」(不穿入也沒有懸空);擒縱各圖的全程不穿入檢查;第 186、187 種的「手柄不壓進凸柱、少抬一點就會壓進」。
- **每張票的完成條件**:該範圍 `npm run verify -- 圖號…` 通過、`npm test` 全過、找伸縮桿的工具與新的一件工具在該範圍不再報出已修的問題、每張改過的圖截四個相位(含斜後方)對照原圖。最後一張票跑全書 `npm run verify`。
