# 依用途瀏覽,取代原書章節

Status: ready-for-agent

**來源:** 2026-10-22 維護者想找某種用途的結構參考卻找不到,經 grilling 決定:頁首的 22 個章節拿掉,改成依**用途**分兩層瀏覽(用途大類 → 用途),另保留**原書順序**。用語見 `CONTEXT.md` 的「用途」「用途大類」「用途瀏覽」「原書順序」(同日更新,「章節」已移除)。

## Problem Statement

網頁頁首的 22 個章節(皮帶與滑輪、齒輪傳動、雜項裝置……)是照原書編號切的連續區段,不是照主題分:同一種用途的機構散在好幾個章節(例如計時相關的散在「擒縱機構」「擺與鐘錶調節」「棘輪與擒縱」「儀錶與周轉輪系」),還有「雜項裝置」(第 350–402 種)、「雜項與旋轉引擎」這種什麼都裝的章節。維護者想找「能拿來做某件事」的結構參考時,只能猜它在哪個章節、再一張張翻,常常完全找不到。

## Solution

- 每個條目掛一個或多個**用途**,用途分屬**用途大類**,兩層。原文寫了用途的(抽水、計時、繪圖、起重……)照原文;原文沒寫、只是通用運動傳遞的,以它要達成的動作當用途(改變轉速、反轉、旋轉變往復、間歇送進……)。
- 用途清單與每個條目掛哪些用途,由 agent 讀完全部 487 個條目的說明後起草並直接套用,維護者不事前審。資料放在一份獨立、好改的「圖號 → 用途」檔,維護者日後看到掛錯就改那一行。
- 打開網頁預設進**用途瀏覽**:頁首第一排是用途大類、第二排是該大類的用途,卡片仍一次一張。翻過一個用途的末張接到下一個用途,翻過大類的最後一個用途接到下一個大類。
- 另有**原書順序**:就是現在的翻法(全部條目依編號一張一張翻),只是頁首沒有頁籤。頁首一個切換鈕在兩種瀏覽間切換,切換時停在同一個條目。
- 卡片上列出該條目的用途(只顯示,不能點)。
- 說明裡的「第 N 種」與「跳到圖號」在用途瀏覽下仍留在用途瀏覽,頁籤跟著換到目標條目的用途,並選中被指定的插圖。
- 不做全文搜尋。

## User Stories

1. 身為維護者,我想依用途大類瀏覽,這樣不知道機構名稱時也能從「我要它做什麼」找起。
2. 身為維護者,我想在一個用途大類底下再選更細的用途,這樣每次只要翻少量條目。
3. 身為維護者,我想讓原文沒寫用途的通用機構也依它要達成的動作(例如「反轉」「改變轉速」)歸到某個用途,這樣齒輪對、皮帶這類條目也找得到。
4. 身為維護者,我想讓一個條目同時出現在它符合的每個用途底下,這樣不管從哪個用途找都找得到它。
5. 身為維護者,我想讓多插圖條目(例如第 19–22 種)掛上各張插圖用途的聯集,這樣任一張插圖的用途都能帶我找到這張卡片。
6. 身為維護者,我想打開網頁就直接進用途瀏覽,這樣主要用法不用多點一下。
7. 身為維護者,我想點一個用途大類就看到它的第一個用途的第一張卡片,這樣切大類後馬上有內容。
8. 身為維護者,我想點一個用途就看到它的第一張卡片,這樣能直接從頭翻這個用途。
9. 身為維護者,我想在一個用途裡依圖號由小到大翻卡片,這樣順序可預期。
10. 身為維護者,我想在一個用途的末張按「下一張」就接到下一個用途的首張,這樣能一路翻完整個用途大類。
11. 身為維護者,我想在大類最後一個用途的末張按「下一張」就接到下一個大類,這樣能一路翻完全部用途,和現在跨章節的翻法一樣。
12. 身為維護者,我想在第一個用途的首張按「上一張」就回到前一個用途的末張(跨大類亦同),這樣往回翻也連續。
13. 身為維護者,我想在整個序列的最前與最後時「上一張」「下一張」變灰,這樣知道到頭了。
14. 身為維護者,我想讓頁籤隨著翻頁跨用途、跨大類而自動標示目前所在,這樣知道自己在哪個用途。
15. 身為維護者,我想看到目前在這個用途裡的第幾張、共幾張,這樣知道還剩多少。
16. 身為維護者,我想在頁尾看到目前的用途大類與用途,這樣截圖或回頭看時知道上下文。
17. 身為維護者,我想在卡片上看到這個條目掛了哪些用途,這樣知道它還屬於哪些用途、日後發現掛錯時知道要改哪裡。
18. 身為維護者,我想用頁首的切換鈕進原書順序,這樣能照原書編號從頭讀。
19. 身為維護者,我想在原書順序裡不看到任何用途頁籤,這樣畫面就是單純的依編號翻頁。
20. 身為維護者,我想在原書順序裡翻頁、鍵盤左右鍵、點圖片左右半邊、手機滑動都和現在一樣,這樣原本的習慣不變。
21. 身為維護者,我想從用途瀏覽切到原書順序時停在同一個條目,這樣切換不會把我丟回第 1 種。
22. 身為維護者,我想從原書順序切回用途瀏覽時也停在同一個條目,並落在它的某個用途裡,這樣兩種瀏覽能互相對照。
23. 身為維護者,我想在用途瀏覽裡點說明中的「第 N 種」時留在用途瀏覽,這樣不會被換到另一種瀏覽方式。
24. 身為維護者,我想點「第 N 種」時,如果目標條目在目前的用途大類裡有用途,就落在那個用途,這樣頁首的大類不會無端跳走。
25. 身為維護者,我想點「第 N 種」時,如果目標條目在目前的大類裡沒有用途,就落在它的第一個用途,這樣規則簡單可預期。
26. 身為維護者,我想點「第 N 種」跳到多插圖條目時選中被指定的那張插圖,這樣和現在的行為一致。
27. 身為維護者,我想跳過去後按「‹ 返回」或 Esc 回到原本的用途、原本的卡片與原本選中的插圖,這樣能多層依序退回。
28. 身為維護者,我想在用途瀏覽裡用「跳到圖號」時套用和「第 N 種」相同的落點規則,但不留返回鍵,這樣它仍是新的閱讀起點。
29. 身為維護者,我想在原書順序裡「第 N 種」與「跳到圖號」的行為和現在一樣,這樣原書順序就是現在的網頁。
30. 身為維護者,我想讓插圖 / 模型的切換在翻頁、切用途、切大類、切換瀏覽方式時都保留,這樣看模型時不用每次重切。
31. 身為維護者,我想讓同一個條目在翻過兩個用途時各出現一次,這樣每個用途都是完整的。
32. 身為維護者,我想用文字編輯器直接改「圖號 → 用途」檔裡的一行,就改掉一個條目掛的用途,這樣修正掛錯不必重跑產生器。
33. 身為維護者,我想在用途檔裡增刪用途或調整用途大類時,`npm test` 會告訴我有沒有條目變成沒有用途、有沒有空的用途、有沒有引用不存在的圖號或用途,這樣改錯馬上知道。
34. 身為維護者,我想用 `file://` 直接開網頁時仍能用兩種瀏覽方式看插圖,這樣和現在一樣不必開伺服器也能看。
35. 身為維護者,我想讓手動驗證清單涵蓋兩種瀏覽方式與它們之間的切換,這樣改畫面後知道要點哪些地方。
36. 身為 agent,我想讓 `node tools/audit.mjs 圖號…` 在條目資料改形狀後照常印出原文,這樣對照原文的工具不壞。

## Implementation Decisions

- **條目資料**:產生器不再切章節,輸出依原書編號排列的單一條目清單(條目的欄位不變:編號、插圖、說明);章節範圍表拿掉。條目資料檔仍是一般 script、由產生器產生、不手改。檔頭註解改成新說法。
- **用途檔**(新):一般 script,手寫維護,不由產生器產生。內容兩部分:
  - 用途大類的有序清單,每個大類有名稱與它的用途的有序清單(用途以名稱識別,名稱在全檔唯一)。
  - 條目 → 用途:鍵是條目的第一張插圖的圖號(數字,維護者看卡片編號的第一個數字就能找到那一行),值是用途名稱的清單,順序即卡片上顯示的順序。
- **用途的起草**:agent 讀全部 487 個條目的說明後起草清單與歸屬,直接套用。原則:
  - 用途大類約 8–12 個,用途名稱短(2–8 字),一個用途通常 3–30 個條目;超過就再細分,太少就併入相近的用途。
  - 一個條目通常掛 1–3 個用途;原文寫了用途的掛那個用途,也可以再掛它達成的動作。
  - 多插圖條目取各插圖用途的聯集。
  - 用途大類與用途的排列順序由起草者決定,以相近的排在一起為原則。
- **瀏覽模組**(新,唯一的測試接縫):不碰畫面的純邏輯,一般 script(掛在全域上),頁面與測試共用。輸入是條目清單與用途檔;對外回答:
  - 目前所在:瀏覽方式、(用途瀏覽時)用途大類與用途、條目、在目前用途裡的第幾張與總張數、是否在序列頭尾、選中的插圖、返回堆疊頂端的條目編號。
  - 動作:翻上一張 / 下一張、選用途大類(落在第一個用途的首張)、選用途(落在首張)、交互參照跳轉(推入返回堆疊)、跳到圖號(清空返回堆疊)、返回、切換瀏覽方式。
  - 用途瀏覽的序列:大類依序、大類內用途依序、用途內條目依第一張插圖的圖號。跨用途、跨大類連續;同一條目在不同用途下各出現一次。
  - 交互參照與跳到圖號在用途瀏覽下的落點:目標條目在目前用途大類裡有用途時,落在其中排最前的那個;否則落在它的第一個用途(依卡片上的用途順序)。選中被指定的插圖。
  - 切換瀏覽方式:停在同一個條目;選中的插圖保留;清空返回堆疊(和手動切頁籤一樣視為新的閱讀起點)。原書順序 → 用途瀏覽的落點,以切到原書順序之前最後所在的用途大類套用上一條的規則;沒有就落在第一個用途。
  - 用途檔的完整性也由這個模組檢查並回報問題清單:每個條目至少一個用途、沒有空的用途、用途名稱不重複、條目 → 用途的鍵都是某條目的第一張插圖、值都是存在的用途。
  - 預設狀態:用途瀏覽、第一個用途大類的第一個用途的首張。
- **頁面**:現有的翻頁、點圖片半邊、鍵盤、手機滑動、返回鍵、跳到圖號都改成呼叫瀏覽模組;頁面只負責畫。
  - 用途瀏覽:頁首兩排頁籤(用途大類、該大類的用途),標示目前所在;頁尾顯示「用途大類 · 用途 · 共 N 圖」。
  - 原書順序:沒有頁籤;頁尾顯示「原書順序 · 共 507 圖」。
  - 頁首一個切換鈕,標示目前的瀏覽方式。
  - 卡片說明之下列出該條目的用途(純文字)。
  - 插圖 / 模型的狀態維持頁面層級,和現在一樣在任何導覽下保留。
  - 頁面在 `file://` 下仍能載入條目資料、用途檔與瀏覽模組(三者都是一般 script);模型照舊在 ES module 載入失敗時不出現。
- **對照原文的工具**:改讀新的條目清單形狀,輸出不變。
- **手動驗證清單**:把「章節頁籤」相關項目改成兩種瀏覽方式,新增用途頁籤、跨用途 / 跨大類翻頁、切換瀏覽方式、用途瀏覽下的交互參照與跳到圖號落點、卡片上的用途字樣。
- 不改模型、檢視器、實體驗證。

## Testing Decisions

- 好的測試只驗外部行為:給條目清單與一份用途檔,呼叫瀏覽模組的動作,斷言它回答的所在位置;不驗內部資料結構。
- 測試用 `node:vm` 載入條目資料、用途檔與瀏覽模組這三個一般 script,放進 `npm test`(零依賴)。
- 導覽行為用小型的假用途檔驗(幾個條目、兩三個大類,含掛多個用途與跨大類的條目),涵蓋:預設狀態;用途內翻頁;跨用途、跨大類翻頁與頭尾;同一條目在兩個用途各出現一次;選大類、選用途的落點;交互參照落在目前大類的用途、或第一個用途;選中被指定的插圖;返回回到原用途、原卡片、原插圖,且可多層;跳到圖號清空返回堆疊;兩個方向的瀏覽方式切換停在同一條目;原書順序的翻頁、跳轉與現在一致。
- 完整性檢查兩邊驗:假用途檔故意做壞(條目沒用途、空用途、重複名稱、不存在的圖號、不存在的用途),斷言每種都被報出;真正的用途檔斷言沒有問題,且 487 個條目全都在用途瀏覽的序列裡至少出現一次。
- 前例:`tests/registry.test.js`(對全書資料逐項斷言完整性);`tools/audit.mjs` 從條目資料檔取出資料的方式。
- 畫面(兩排頁籤、切換鈕、卡片上的用途、頁尾)不自動測,靠手動驗證清單。

## Out of Scope

- 全文搜尋。
- 卡片上的用途可點擊跳轉。
- 維護者事前審核用途清單或歸屬。
- 用途掛在個別插圖上。
- 依運動轉換或依零件的第二種分類。
- 保留舊章節名稱(在任何畫面上)。
- 原書順序的新功能(原書順序維持現在的翻法)。
- 模型、檢視器、實體驗證的任何改動。
