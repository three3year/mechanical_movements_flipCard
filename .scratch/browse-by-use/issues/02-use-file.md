# 02 — 用途檔:起草全部條目的用途,加上完整性檢查,卡片顯示用途

**What to build:** 每個條目都有**用途**,分屬**用途大類**(用語見 `CONTEXT.md`)。agent 讀完全部 487 個條目的說明(約 5.4 萬字,只讀說明文字、不必讀模型),起草用途大類、用途與每個條目的歸屬,寫進手寫維護的**用途檔**(一般 script;格式與起草原則見規格 `.scratch/browse-by-use/spec.md` 的「用途檔」「用途的起草」)。瀏覽模組能檢查用途檔的完整性並回報問題清單。網頁上(仍是原書順序)每張卡片在說明之下列出它的用途,純文字、不能點。

**Blocked by:** 01 — 原書順序:條目改單一清單,翻頁交給瀏覽模組

**Status:** ready-for-agent

- [ ] 用途檔:用途大類的有序清單(每個大類有名稱與它的用途的有序清單,用途名稱全檔唯一);條目 → 用途,鍵是條目第一張插圖的圖號,值是用途名稱清單(順序即卡片上的顯示順序)
- [ ] 起草照規格原則:用途大類約 8–12 個;用途名稱 2–8 字、一個用途通常 3–30 個條目;一個條目通常 1–3 個用途;原文寫了用途的照原文,原文沒寫的以它要達成的動作當用途;多插圖條目取各插圖用途的聯集;相近的排在一起。維護者不事前審,直接套用
- [ ] 瀏覽模組的完整性檢查報出:條目沒有用途、空的用途、用途名稱重複、鍵不是任何條目的第一張插圖、值是不存在的用途
- [ ] `npm test`:假用途檔逐一做壞上述五種,各被報出;真正的用途檔沒有問題
- [ ] 卡片說明之下列出該條目的用途(純文字);用途檔載入失敗時卡片照常顯示、只是沒有用途
- [ ] `npm test` 全過
