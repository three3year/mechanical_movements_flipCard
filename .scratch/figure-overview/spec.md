# 插圖總覽:全部插圖一頁看完,點一格打開卡片

Status: done

**來源:** 2026-10-26 維護者想一眼看過全書插圖、從圖找機構,經 grilling 決定新增第三種瀏覽方式**插圖總覽**。用語見 `CONTEXT.md` 的「插圖總覽」(同日新增)、「插圖」「條目」「卡片」「原書順序」「用途瀏覽」。

## Problem Statement

網頁一次只顯示一張卡片。維護者常常只記得機構長什麼樣子,不記得圖號、也不確定它掛在哪個用途。現在要找只能一張張翻(全書 487 張卡片、507 張插圖),或猜圖號再用「跳到圖號」碰運氣。沒有地方能一次看到所有插圖、從外形認出要找的那一個。

## Solution

- 頁首的瀏覽方式切換鈕從兩個變三個:【依用途】【插圖總覽】【原書順序】。
- **插圖總覽**把全書 507 張插圖依圖號排成一整面圖塊,不分頁、一路往下捲。每張插圖一格(多插圖條目的每張各佔一格),格子約 120 px 見方,插圖等比縮放置中,格子上只有圖;滑鼠停在格子上提示「第 N 種」。
- 總覽裡沒有用途頁籤、「上一張/下一張」、「跳到圖號」與返回鍵,只有圖塊。
- 點一格:切到**原書順序**,顯示該插圖所在條目的卡片並選中那張插圖(例如點第 21 種,打開第 19–22 種的卡片、選中圖 21);之後「下一張」就是下一個圖號的條目。
- 看完卡片再按【插圖總覽】:捲到目前卡片選中的插圖,並把那一格標出來。翻到別張後再回總覽,捲到的是翻到的那張。
- 圖片區的插圖/模型狀態不受總覽影響:總覽一律只有插圖,點進卡片後照原本的插圖或模型模式顯示。
- 開網頁仍預設進用途瀏覽。

## User Stories

1. 身為維護者,我想在頁首切到插圖總覽,這樣能一次看到全書的插圖。
2. 身為維護者,我想讓總覽不分頁、一路捲下去,這樣不用一頁頁翻也能看完全部。
3. 身為維護者,我想讓插圖依原書圖號排列,這樣大略知道圖號範圍時也能捲到附近。
4. 身為維護者,我想讓多插圖條目的每張插圖各佔一格,這樣第 19–22 種的四張圖都看得到、都能點。
5. 身為維護者,我想讓每格大小一致、插圖等比縮放置中,這樣格線整齊,長寬比不同的插圖也不變形。
6. 身為維護者,我想讓格子上只有圖,這樣畫面乾淨、專心看外形。
7. 身為維護者,我想滑鼠停在格子上時看到「第 N 種」,這樣不用點進去也知道圖號。
8. 身為使用螢幕閱讀器的讀者,我想讓每格唸出「第 N 種」,這樣不看圖也知道每格是哪一張。
9. 身為維護者,我想在桌機一排看到好幾格、在手機一排至少幾格,這樣兩種裝置都能快速掃過。
10. 身為維護者,我想讓總覽的插圖捲到附近才載入,這樣切到總覽時不用一次下載全部 507 張圖。
11. 身為維護者,我想點一格就打開該插圖所在條目的卡片,這樣認出外形後能馬上讀說明。
12. 身為維護者,我想點多插圖條目裡的某一格時,卡片選中的是我點的那張,這樣看到的就是我認出的那張圖(與它的模型)。
13. 身為維護者,我想點格子後以原書順序顯示卡片,這樣「上一張/下一張」翻到的就是總覽裡它旁邊的插圖。
14. 身為維護者,我想點格子是一個新的閱讀起點,這樣先前交互參照留下的返回鍵不會出現。
15. 身為維護者,我想看完卡片後再按【插圖總覽】回到總覽,這樣能繼續找下一個。
16. 身為維護者,我想回到總覽時捲到目前卡片選中的插圖並標出那一格,這樣知道自己剛看到哪裡。
17. 身為維護者,我想點進卡片後翻了幾張再回總覽時,捲到的是翻到的那張,這樣總覽和卡片的位置一致。
18. 身為維護者,我想從用途瀏覽的卡片切到總覽時,總覽也標出那張卡片的插圖,這樣從哪種瀏覽方式來都一樣。
19. 身為維護者,我想在總覽裡看不到用途頁籤、翻頁鍵與跳到圖號,這樣畫面只剩圖塊、不會按到在總覽裡沒意義的東西。
20. 身為維護者,我想在總覽裡按鍵盤 ← → 或在手機左右滑時不會翻頁,這樣捲動總覽不會被打斷。
21. 身為維護者,我想從總覽直接按【原書順序】時回到總覽前所在的卡片,這樣誤切到總覽可以原路回去。
22. 身為維護者,我想從總覽直接按【依用途】時,落點和從那張卡片切到依用途一樣(停在同一條目、優先切走前所在的用途大類),這樣三種瀏覽方式的切換規則一致。
23. 身為維護者,我想讓頁尾在總覽中寫「插圖總覽 · 共 507 圖」,這樣知道總覽涵蓋全書。
24. 身為維護者,我想在圖片區是模型模式時切到總覽、再點一格,卡片仍顯示模型(若有),這樣插圖/模型的選擇不因總覽而重設。
25. 身為維護者,我想讓用途檔載入失敗時切換鈕仍出現(只有【插圖總覽】【原書順序】),這樣總覽不依賴用途檔。
26. 身為維護者,我想讓切換鈕標示目前所在的瀏覽方式,這樣知道自己在總覽還是在卡片。

## Implementation Decisions

- **插圖總覽是瀏覽模組的第三種瀏覽方式。** 導覽邏輯都在瀏覽模組(`createBrowser` 回傳的物件),頁面只照 `where()` 的回答畫,和用途瀏覽、原書順序一樣。
- **進總覽**:`setMode("overview")`。總覽不改變「目前所在的卡片」(條目與選中的插圖),只是不顯示它;切走前若在用途瀏覽,照現行規則記下所在用途大類。和其他切換一樣,返回堆疊清空。
- **總覽中的 `where()`**:`mode` 為 `"overview"`,另回答全部插圖的圖號(依圖號排,507 個)與要標出的那一格——目前卡片選中的插圖;選中的插圖由頁面決定(`figure` 為 null)時,標條目的第一張插圖。
- **點一格**:新增一個動作(例如 `open(no)`),只在總覽中有效:切到原書順序、落在該圖所在條目、選中該圖、返回堆疊清空;圖號不存在時不動並回答失敗。
- **從總覽切到其他瀏覽方式**:`setMode("book")`、`setMode("use")` 以「目前所在的卡片」為起點,落點規則和現行從卡片切換相同(原書順序停在同一條目;用途瀏覽優先落在切走前所在用途大類裡的用途)。
- **沒有用途檔時**:序列只有原書順序與總覽,切換鈕顯示兩個;總覽照常可用。
- **頁面**:切換鈕依序是【依用途】【插圖總覽】【原書順序】。總覽中隱藏用途頁籤、翻頁列、跳到圖號、返回鍵與卡片;鍵盤 ← → 與滑動翻頁在總覽中不作用。格線用自動填滿的方格(約 120 px),插圖延遲載入;每格的替代文字與工具提示是「第 N 種」。回到總覽時把標出的那一格捲進畫面中央。
- **頁尾**:總覽中是「插圖總覽 · 共 507 圖」。

## Testing Decisions

- 好的測試只透過瀏覽模組的公開動作(`setMode`、`open`、`step`、`goto`、`selectFigure`……)與 `where()` 的回答斷言,不碰內部序列或欄位。
- 唯一的接縫是瀏覽模組;測試加在既有的瀏覽模組測試裡(用 `node:vm` 載入頁面的三個 script),沿用它的小型假條目與真資料兩種寫法。要涵蓋:
  - 切到總覽:`where()` 回答 507 個圖號依序排列;標出的是目前卡片選中的插圖,沒有指定時是條目的第一張插圖。
  - 點一格:落在原書順序、正確條目、選中該圖、返回堆疊清空;點多插圖條目的非第一張也選中它;不存在的圖號不動。
  - 在卡片翻頁或跳到圖號後再切到總覽,標出的跟著變。
  - 從總覽切到原書順序與用途瀏覽的落點,和從卡片直接切換相同;從用途瀏覽進總覽後切回,優先落在原用途大類。
  - 沒有用途檔時仍可進總覽與點格。
- 畫面(格線、延遲載入、捲到該格、隱藏的元件、鍵盤與滑動不翻頁)不寫自動測試:用截圖服務截總覽與回總覽後的畫面,並在手動驗證清單的「用途瀏覽與原書順序」一節加總覽的項目。

## Out of Scope

- 總覽依用途分段或篩選。
- 總覽中跳到圖號、搜尋。
- 格子上顯示圖號或「有模型」標記。
- 記住上次的瀏覽方式或總覽捲動位置(重新整理後仍預設進用途瀏覽)。
- 另開獨立網頁、網址帶圖號直接打開某張卡片。
- 為總覽另做縮圖檔(直接用原插圖,靠延遲載入控制下載量)。

## Further Notes

- 「原書順序」的 Avoid 已有「預覽模式」;新瀏覽方式的名稱刻意用「插圖總覽」,不用「圖示預覽」,避免和它混淆。
- 全書插圖約 24 MB,單張約 200 px 寬;延遲載入讓切到總覽時只下載畫面附近的圖。
