# 截圖服務:所有截圖共用一個瀏覽器

Status: ready-for-agent

**來源:** 2026-10-16 掃第 301–400 種時,12 個子代理各自截圖,CPU、記憶體、硬碟都衝到 100%。同日 grilling 定下的做法如下;量測(這台電腦,i5-11500、GTX 1650、16 GB)寫在 Further Notes。

## Problem Statement

模型檢查要截很多圖(第 301–400 種一輪約 400 張)。現在每個子代理每截一張就自己執行一次 `chrome --headless --screenshot`:一個 Chrome 帶出 6–10 個子行程,12 個子代理同時截就是幾十個;指令參數強制用 CPU 模擬繪圖(SwiftShader),一張就吃滿一顆核心;機器一滿載,固定的時間預算不夠,截出空白圖,子代理再重試,負載更高;有的子代理為了避開互相干擾,每次另建一個 Chrome 設定檔,一個子代理的資料夾就到 1.3 GB。

另外,`chrome --screenshot` 不等頁面畫完,只照時間預算截,所以 `model-strip.html` 一頁並排多個相位的設計用不上——在沒負載時實測也只畫出第一個相位,子代理只好一個相位開一次 Chrome。視窗寬度要子代理自己算,算錯就把換行的相位切掉。更早幾輪用 Playwright MCP,多個子代理共用一個分頁,會互相蓋掉。

## Solution

一個常駐的截圖服務:主 session 在需要截圖的那次 prompt 開始時啟動、回覆前關閉;它同時提供專案的靜態檔,只開一個 headless Chrome(先用顯示卡,拿不到才用 CPU 模擬),所有截圖——主 session 自己的與每個子代理的——都經由一個命令列小工具送給它排隊。服務一次只畫一頁、在各個呼叫之間輪流,等頁面標題變成 `ready` 才截,寬度固定 1800、高度依內容,長邊超過 2000 就在列與列之間切成多張。專案的 CLAUDE.md 與模型檢查的規格改成一律用它。

## User Stories

1. As a 維護者, I want 同時開很多子代理截圖時電腦不會滿載, so that 我還能用這台電腦做別的事。
2. As a 維護者, I want 不論開幾個子代理,截圖都只有一個 Chrome 在跑, so that 行程數、記憶體與硬碟用量是固定的。
3. As a 維護者, I want 截圖預設用顯示卡畫, so that 不吃 CPU、每張更快。
4. As a 維護者, I want 拿不到顯示卡時自動改用 CPU 模擬, so that 在遠端桌面或沒有顯示卡的電腦上照樣能截。
5. As a 主 session, I want 啟動指令等 Chrome 就緒、查完實際的繪圖器才結束,並印出一行「截圖服務就緒:GPU(顯示卡名稱)」或「…:CPU 模擬(拿不到 GPU,每張較慢)」, so that 我知道服務能用、用的是哪一種。
6. As a 主 session, I want 在一次 prompt 開始時判斷這次要不要截圖(自己截或派子代理截),要就啟動服務, so that 服務只在需要的時候佔資源。
7. As a 主 session, I want 回覆前關閉服務,關閉時 Chrome 與它的暫存設定檔一起清掉, so that 不留下殘留的行程與檔案。
8. As a 主 session, I want 啟動時若上一次沒關乾淨(例如 session 中斷),先清掉殘留的服務與 Chrome, so that 不會累積孤兒行程。
9. As a 主 session, I want 服務同時提供專案的靜態檔, so that 不用另開 python 或其他靜態伺服器、只開關一個東西。
10. As a 子代理, I want 用一個命令列工具截圖(給頁面與輸出路徑), so that 我照常用 Bash 就能截,不用學新的介面。
11. As a 子代理, I want 一次呼叫送最多 6 個頁面, so that 一張圖的幾個視角可以一起送。
12. As a 子代理, I want 一次送超過 6 頁時被拒絕並說明要分批, so that 一個大批不會讓自己的呼叫超時。
13. As a 子代理, I want 工具等這次的頁面全部畫完才結束,一行印一個寫出的檔案與寬高, so that 我知道去哪裡看圖。
14. As a 子代理, I want 等待時工具每隔幾秒印「前面還有幾頁、預估幾秒」, so that 我知道它在排隊,不是卡住。
15. As a 子代理, I want 服務在各個呼叫之間輪流畫(像發牌), so that 我送的兩頁不用等別人的六頁全部畫完。
16. As a 子代理, I want 服務沒開時工具直接失敗並說明「截圖服務沒在跑,請回報主 session 啟動」, so that 我回報主 session,而不是自己開 Chrome。
17. As a 子代理, I want 工具在接近 10 分鐘時自己報錯結束, so that 服務出問題時我不會無限等。
18. As a 子代理, I want 專案內的頁面等標題變成 `ready` 才截(變成 `error` 時回報錯誤與頁面上的訊息), so that 截到的是畫完的畫面,不是空白。
19. As a 子代理, I want `model-strip.html` 的多個相位一次截完, so that 一張圖只排一次隊,不用每個相位各截一次。
20. As a 子代理, I want 能截外部網址(例如 507movements.com 的動畫頁),等我指定的秒數再截, so that 對照網站時也不用自己開 Chrome。
21. As a 子代理, I want 截圖寬度預設 1800、高度依內容,可以另給寬度, so that 不用自己算視窗寬度,相位換行也不會被切掉。
22. As a 子代理, I want 長邊超過 2000 px 時自動切成多張(`名稱-1.png`、`名稱-2.png`…), so that 我讀圖時不會被等比例縮小到看不清。
23. As a 子代理, I want 切線只落在沒有任何小圖(img、canvas)跨過的高度, so that 一個相位或一張插圖不會被切在兩張 PNG 之間。
24. As a 子代理, I want 單一張小圖本身就高過 2000 時,它自己成一張並在輸出裡註明會被縮小, so that 我知道那張看到的是縮小的。
25. As a 子代理, I want 一定要給輸出路徑、沒給就報錯, so that 圖放在我決定的地方(例如 gitignore 的 `.playwright-mcp/model-audit/`)。
26. As a 子代理, I want 一個頁面載入失敗時只有那一頁回報錯誤、其他頁照樣截, so that 一頁的錯不會拖垮整批。
27. As a 子代理, I want 頁面在合理時間內沒變成 `ready` 時回報逾時與目前的標題, so that 我知道是頁面的問題,不是排隊的問題。
28. As a 維護者, I want 每頁在自己的分頁裡開、截完就關, so that 頁面之間不互相影響,記憶體不累積。
29. As a 維護者, I want 服務不需要任何新套件(用 Node 內建的 WebSocket 講 Chrome 的除錯協定、用電腦上已裝的 Chrome,找不到就用 Edge), so that 專案維持零依賴。
30. As a 維護者, I want CLAUDE.md 的「開發」寫明:截圖一律經截圖服務、由主 session 決定開關、子代理發現沒開就回報、執行工具時逾時設 10 分鐘、不要自己執行 `chrome --headless`、不要用 Playwright MCP 截圖, so that 每個 session 與子代理都照這個規則。
31. As a 維護者, I want `docs/agents/model-audit.md` 第 3 步「看動作」改成用截圖服務,並說明一張圖一次截多個相位、讀圖時長邊超過 2000 會被縮小, so that 模型檢查的子代理照新的方式截。
32. As a 維護者, I want 截圖服務的行為有不需要 Chrome 的自動測試(`npm run test:shot`), so that 改它時知道沒壞,在沒有顯示卡的環境也能跑。

## Implementation Decisions

- **兩個新工具**(放在專案的工具資料夾):截圖服務(常駐的 Node 行程,啟動、關閉也由它的指令負責)與命令列 client。兩者只用 Node 內建模組;不加任何套件。
- **服務的組成**:一個靜態檔伺服器(提供專案根目錄,取代另開的 python 伺服器)+ 一個 headless Chrome(只開一個,用自己的暫存設定檔)+ 一個排隊器。client 與服務之間用本機 HTTP;服務與 Chrome 之間用 Chrome DevTools Protocol(Node 內建的 WebSocket)。
- **連接埠**:固定一個預設值,可用環境變數覆寫;靜態檔與 client 要求共用同一個埠。
- **啟動指令**:找電腦上的 Chrome(找不到用 Edge);先試顯示卡模式,開一個測試頁讀 WebGL 的繪圖器名稱,名稱是 SwiftShader 或拿不到時,重開成 CPU 模擬模式;就緒後印一行繪圖方式,然後讓服務留在背景、指令結束。啟動前若發現上一次的服務或 Chrome 還在(記錄行程編號的檔案),先清掉。
- **關閉指令**:關 Chrome、刪暫存設定檔、結束服務;服務沒在跑時不算錯誤。
- **繪圖方式只告訴主 session**:只在啟動指令印出;client 的輸出不帶繪圖方式(GPU 與 CPU 模擬畫出來的圖一樣,只差速度)。
- **client 的介面**:一次給 1–6 個頁面,每頁一個網址(專案內的相對路徑或外部網址)與一個輸出路徑;可選寬度(預設 1800)、外部頁的等待秒數。超過 6 頁、沒給輸出路徑、服務沒在跑,都直接失敗並說明原因。等待時每隔幾秒印排隊狀態;完成後一行印一個寫出的檔案與寬高,失敗的頁印原因;接近 10 分鐘還沒完成就報錯結束。
- **排隊**:服務一次只畫一頁。每個還在等的呼叫各一條隊伍,輪流從下一條隊伍拿一頁(像發牌);6 頁的上限與輪流都以「頁」為單位,不以輸出的 PNG 張數計。
- **畫一頁**:開一個新分頁,視窗寬度用指定值、高度先給足;專案內的頁面等 `document.title` 變成 `ready`(變成 `error` 就回報錯誤與頁面上的訊息),外部頁等指定的秒數;逾時就回報逾時與當下的標題。畫完量內容的實際高度,截整頁,關分頁。
- **切圖**:長邊超過 2000 px 時,在頁面上量所有 img、canvas 的上下緣,切線只取沒有任何一張跨過的高度,從上往下每段取不超過 2000 的最遠切點;某一張小圖本身超過 2000 就自己成一段,並在回應裡標出「會被縮小」。只有一段時輸出原檔名;多段時檔名加 `-1`、`-2`…。
- **現有頁面**:`model-strip.html`、`model-preview.html`、`contact-sheet.html` 畫好後都已把標題改成 `ready`,不用改。`model-strip.html` 在 1800 寬時一列放 5 張(插圖 + 4 個相位),相位多了會自然換行。
- **規範**:CLAUDE.md 的「開發」加一條(見 User Story 30);`docs/agents/model-audit.md` 第 3 步改寫(見 User Story 31),拿掉現在教的 `chrome --headless --use-angle=swiftshader…` 指令與 Playwright 的寫法。
- **不寫進 CONTEXT.md、不寫 ADR**:截圖服務是開發工具,不是維護者談模型時的用語;選擇也容易改回來。

## Testing Decisions

- **一個接縫:命令列工具**。測試啟動一個截圖服務,但把「畫一頁」換成假的元件(收到網址就回傳定好的內容高度、各小圖的位置與一張假的圖片,也能模擬變慢、`error`、逾時),然後像子代理一樣執行命令列工具,只驗外部看得到的行為:印出的檔案與寬高、寫出的檔案、錯誤訊息與結束碼。不需要 Chrome,在沒有顯示卡的環境也能跑。
- **要驗的行為**:
  - 輪流畫:A 送 6 頁、B 稍後送 2 頁,B 在 A 之前完成,畫的順序是交錯的。
  - 超過 6 頁、沒給輸出路徑、服務沒開:各自失敗、訊息說明怎麼辦(服務沒開時叫你回報主 session)。
  - 切圖:內容高 3000、小圖每列 304 px 時,切成兩張且每條切線都不跨過任何小圖;長邊不超過 2000 時只輸出一張、檔名不變;一張小圖高 2500 時它自己成一張並標出會被縮小。
  - 一頁 `error` 或逾時:只有那一頁回報失敗,其他頁照樣寫出。
  - 等待中會印排隊狀態。
- **放在新的 `npm run test:shot`**:`npm test` 只驗模型定義、`npm run test:verify` 是實體驗證自己的,都不放。用 Node 內建的測試執行器,和其他兩個一樣。
- **真的 Chrome 只做手動冒煙測試**:啟動服務(看到繪圖方式那一行)、截 `model-strip.html` 的一張 4 個相位與一張 30 個相位(切成兩張、相位完整)、截一個外部網址、關閉後確認沒有殘留的 Chrome 行程。結果寫在票的 Comments。
- **前例**:實體驗證自己的測試(`npm run test:verify`)用小的假場景驗工具行為,不碰全書;這裡同樣用假的「畫一頁」驗服務的行為。

## Out of Scope

- 限制同時跑的子代理數(包括同時跑 `npm run verify` 的 Rapier 也吃 CPU):這次沒有決定,不做。
- 改 `model-strip.html` 等頁面的版面或參數。
- 已存的截圖搬家或清理;上一輪的截圖照舊留在 `.playwright-mcp/model-audit/`。
- 模型檢查以外的截圖流程(例如網頁本身的手動驗證清單)不強制改,但規範一樣適用。

## Further Notes

- 量測(2026-10-16,這台電腦,一個 headless Chrome、沒負載):Chrome 啟動約 1 秒;一張 4 個相位的 `model-strip.html` 用 GPU 0.6–1.7 秒、用 CPU 模擬 0.8–2.1 秒;GPU 模式的 WebGL 繪圖器回報「NVIDIA GeForce GTX 1650, Direct3D11」,CPU 模擬回報「SwiftShader」。以一次一頁、每頁約 1.2 秒估,12 個子代理同時各送 6 頁,排最後的約等 1.5 分鐘,10 分鐘的逾時有約 6 倍餘裕。
- 寬度上限:headless 的視窗不受螢幕限制,但寬度超過約 16384 px 的部分會畫錯(顯示卡單張貼圖的上限),所以可另給的寬度上限是 16384。
- 讀圖的限制:讀圖時長邊超過 2000 px 會等比例縮到 2000(1800×3000 看到 1200×2000,1800×8000 看到 450×2000),所以預設的長邊上限是 2000。
- 實際行程數:這次掃描中途看到 73 個 chrome 行程(含使用者自己的瀏覽器),其中 headless 殘留 16 個;子代理各自建的 Chrome 設定檔共 61 個,最大的一個子代理資料夾 1.3 GB。
