## Problem Statement

第 301–400 種的實體驗證(100 張、0 個未豁免、94 項豁免)與測試都通過,但掃描查出 217 筆維護者看網頁會退回的問題(第 16 族後段 14、第 17 族 18、第 18 族 14、第 19 族 23、第 20 族 37、第 21 族 37、第 22 族 39、第 23 族 35):

- 整張讀錯或讀反:第 298 種之後又有好幾張——第 330 種的曲柄軸其實橫在紙面上、第 332 種的固定樞軸是 F、第 357 種左右顛倒且槓桿會伸縮、第 368 種的傳動、第 373 種的指示器、第 398 種其實是槽凸輪、第 400 種凸輪軸差 90°、第 310 種的豎琴形框架是重力臂。
- 轉向或作用的方向反了:第 306、307 種、第 334 種滾子、第 360 種鼓輪、第 366 種槓桿把鑽桿抬起、第 371 種大輪、第 376 種馬、第 377 種人、第 386 種側件裝反、第 388 種兩個滾子、第 391 種齒輪。
- 零件的各塊不相連、樞軸沒有銷、支架與汽缸浮在空中、曲柄臂浮在曲柄軸前面、連桿接點深度不相接(第 3 類最多;平行運動與引擎兩族幾乎每張都有)。
- 會伸縮的桿:第 357 種 leverN、第 366 種三根、第 378 種連桿,都找不到實物理由;第 359、390 種的繩或皮帶長度會變。
- 說「夾」「推」「靠」「導」的一對零件沒碰到或整個穿進去:第 318 種插梢沒夾住游絲、第 327 種滾子、第 351 種導座、第 361 種兩根銷頭對頭、第 379、380 種鑽頭碰不到工件、第 342 種鏈條不夠長。
- 豁免的原因寫錯,蓋住了真問題(第 337、339、342、343、345、350、354、366、368、371、377、379、380、385、395、398、399 種等)。
- 外在缺了:擒縱與鐘錶的驅動、第 342 種的抽水桿、第 351 種的臼、第 357 種的閥、第 372 種的皮帶與重錘、第 395 種的汽缸。
- 讀者看不出來:關鍵接觸被前面的零件蓋住、轉向箭頭關掉或永遠不出現(第 355、356 種只用四元數)、切換狀態時指針不動(第 373 種沒標 posed)、補償或調節的結果看不出來。
- 工具的盲點:實體驗證把大圓柱沿自己軸向的相對滑動當成「軸在孔裡」放過(第 368 種標記點埋進圓筒 0.67、第 373 種小車輪)。

## Solution

照八份報告的建議修法與維護者 2026-10-14 的決定,把 217 筆問題修掉;修不了的照實寫成豁免、原因以「未修:」開頭並列進待確認清單。修完每一筆在報告裡加「狀態:已修(日期):做了什麼」,重新發布報告的鏡像。

先做跨圖的改動(實體驗證的盲點、只用四元數的零件的轉向箭頭、共用的引擎與擒縱模組),再修各圖自己的問題。整張讀錯的圖照原圖重做;擒縱與鐘錶輪系補擺、擺輪與重錘,沿用 `weightDrive`(範圍見本規格「需要你決定的」)。

## Testing Decisions

- **接縫**:沿用現有的兩個——模型定義(`npm test`,對各圖匯出的 pose() 與接觸函式下斷言)與實體驗證(`npm run verify`)。實體驗證的盲點那張票改的是實體驗證自己的判斷,用它自己的測試(`npm run test:verify`)先寫失敗的例子(大圓柱沿軸向穿入另一個零件)。不新增接縫;截圖對照照 `docs/agents/model-audit.md` 的做法手動做。
- **好的斷言**:對到原文的一句(例:「叉瓦隨之落下、由重量給衝量」「讓活塞桿上部從叉中間穿過」「傾向變為垂直」),或對到接觸(相碰的一對間隙接近 0、少轉一點就穿入、全程不穿入),或對到守恆(桿長、繩長、皮帶長不變)。不要只數零件的塊數或重複模型自己的公式;這次掃描抓到測試鎖住錯誤行為的例子(第 368 種齒條速度、第 389、390 種原文沒說的齒數、第 397 種停半圓),改成對到原文或放寬成範圍。
- **每筆先寫失敗的測試再改模型**(TDD),能用斷言表達的都要有斷言;純外觀的(箭頭位置、字母、顏色、取景、遮擋)以截圖確認並寫進報告。
- **前例**:第 234、238 種與第 288–300 種的重錘驅動測試(繩長不變、繩繞在鼓上、拉力讓輪往前轉、輪停重錘停、降到底捲回);第 299 種「從正面看叉瓦被蓋住的比例」;第 129 種繩捲在鼓上;第 336 種平行運動的「桿長不變、十字頭偏離直線」;第 287 種進程型調速器與節流閥。
- **每張票的完成條件**:該範圍 `npm run verify -- 圖號…` 通過、`npm test` 全過、`node tools/rigid-links.mjs` 與 `node tools/one-piece.mjs` 在該範圍不再報出已修的問題(剩下的每一項寫出理由)、每張改過的圖截四個相位(含斜後方)對照原圖。最後一張票跑全書 `npm run verify`。
