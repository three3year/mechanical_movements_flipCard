# 可操作的 3D 模型（第一章試點）

Status: ready-for-agent

## Problem Statement

讀者在卡片上只看得到原書的靜態版畫插圖和文字說明。很多條目的重點是「運動」：兩輪同向或反向、皮帶移到哪個輪就正轉或反轉、拉繩多長重物才升多少。只看一張靜止的圖，這些關係很難想像，必須在腦中自己「轉轉看」。讀者想實際動手操作每一個機構，看它怎麼動。

## Solution

讓插圖有對應的**模型**：一個可操作的 3D 重現，畫風是仿原書的線稿風。卡片圖片區可以在「插圖 / 模型」之間切換。進入模型後，機構會自動慢速運轉。讀者抓住**主動件**拖動，就能親手帶動整個機構；在空白處拖動則是轉視角，看清楚空間配置。原文有描述操作的條目（例如把皮帶移到空轉輪、壓下張緊輪），在模型旁提供按鈕切換狀態。滑輪組條目會即時顯示省力比與位移，原文提到的字母標籤（A、B、C）會標在零件上。

零件連動依幾何關係計算，不使用物理碰撞引擎（見 ADR-0001）。第一階段只做第一章「皮帶與滑輪」的 23 張插圖。

## User Stories

### 切換與瀏覽

1. 身為讀者，我想在卡片圖片區看到「插圖 / 模型」切換，這樣我可以在原圖和可操作的模型之間來回對照。
2. 身為讀者，我想只在有模型的條目看到這個切換，這樣沒有模型的卡片不會出現無用的按鈕。
3. 身為讀者，我想剛開網頁時預設顯示插圖，這樣原本的閱讀體驗不受影響。
4. 身為讀者，我想切到模型後翻到下一張時仍停在模型模式，這樣我能一路玩完整章。
5. 身為讀者，我想在模型模式下翻到沒有模型的卡片時看到插圖，再翻到有模型的卡片時自動回到模型，這樣模式不會因為中間一張沒有模型而被重設。
6. 身為讀者，我想在模型模式下仍能用「上一張 / 下一張」按鈕和鍵盤左右鍵翻頁，這樣翻頁的方式不會消失。
7. 身為讀者，我想在模型模式下點擊或滑動圖片區時不會翻頁，這樣我拖動模型時不會誤翻到別張。
8. 身為讀者，我想切回插圖模式後，點擊圖片左右半邊和手機左右滑動又能翻頁，這樣插圖模式的行為和現在一樣。
9. 身為讀者，我想在模型模式下點說明文字裡的「第 N 種」交互參照時，跳過去仍顯示模型，這樣我能直接比較兩個機構的動作。
10. 身為讀者，我想從交互參照按「返回」時回到原本那張卡片的模型，這樣比較完可以接著玩。

### 多插圖條目

11. 身為讀者，我想在多插圖條目（如第 16–17、19–22 種）的模型模式下看到一排「圖 19 / 20 / 21 / 22」的圖號小頁籤，這樣我可以逐一操作每張插圖的模型。
12. 身為讀者，我想一次只顯示一個模型，這樣手機不會因為同時跑好幾個 3D 而卡頓。
13. 身為讀者，我想透過交互參照「第 20 種」跳過來時，小頁籤直接選在圖 20，這樣我看到的就是被引用的那一個。
14. 身為讀者，我想進入多插圖條目時預設選第一張插圖的模型，這樣有固定的起點。

### 操作主動件

15. 身為讀者，我想按住主動件拖動來轉動整個機構，這樣有親手操作的感覺。
16. 身為讀者，我想主動件有明顯的強調色，這樣我一眼就知道哪個零件可以抓。
17. 身為讀者，我想游標移到主動件上時會改變樣式，這樣我知道現在按下去是轉零件、不是轉視角。
18. 身為讀者，我想拖曳旋轉型主動件（皮帶輪、曲柄）時，零件跟著我手指繞軸心的角度轉，這樣操作直覺。
19. 身為讀者，我想在滑輪組裡拖的是繩端，拉下去重物就上升，這樣跟原文描述的施力方式一致。
20. 身為讀者，我想晃動型主動件（如第 6 種的槓桿）只能在合理角度範圍內擺動，這樣模型不會做出原機構不可能的動作。
21. 身為讀者，我想繩端或槓桿拖到極限就停住，這樣重物不會穿過滑輪、槓桿不會轉過頭。
22. 身為讀者，我想從動件即時跟著主動件動，這樣我能看出兩者的轉向和快慢關係。
23. 身為讀者，我想在觸控螢幕上用手指拖主動件也能操作，這樣手機上也能玩。

### 視角

24. 身為讀者，我想在空白處拖動來旋轉視角，這樣我能看清楚第 3、4、11 種這類兩軸成直角的空間配置。
25. 身為讀者，我想用滾輪或雙指縮放，這樣我能看細節或看全貌。
26. 身為讀者，我想模型一開始的視角接近原書插圖的角度，這樣切換時對得上。
27. 身為讀者，我想有一個「重設視角」的方法，這樣轉亂了可以回到原本的角度。

### 播放

28. 身為讀者，我想切到模型時它自動慢速運轉，這樣我立刻知道它是會動、可以操作的。
29. 身為讀者，我想抓住主動件時自動播放立刻暫停，這樣播放不會跟我的手搶。
30. 身為讀者，我想放開主動件後維持暫停，這樣我能停在某個姿勢仔細觀察。
31. 身為讀者，我想有播放 / 暫停按鈕，這樣我能隨時讓它繼續轉。
32. 身為讀者，我想調整播放速度，這樣我能放慢看細節，或加快看整體效果。
33. 身為讀者，我想有範圍限制的主動件（繩端、槓桿）在自動播放時來回往復，這樣播放不會卡在極限不動。
34. 身為讀者，我想翻到別張再回來時模型重新從預設狀態開始，這樣每次進入都有一致的起點。

### 狀態切換

35. 身為讀者，我想在第 2 種模型旁用按鈕切換「開口皮帶 / 交叉皮帶在固定輪上」，這樣能看到不停止驅動端也能反轉從動軸。
36. 身為讀者，我想在第 5 種模型旁用按鈕「壓下 / 放開」張緊輪 B，這樣能看到放開時皮帶太鬆、從動輪不轉。
37. 身為讀者，我想在第 7 種模型旁用「左輪 / 中輪 / 右輪」按鈕移動皮帶，這樣能看到直立軸正轉、停止、反轉。
38. 身為讀者，我想在速度皮帶輪與錐形皮帶輪（第 8–10 種）用按鈕把皮帶移到不同段，這樣能看到從動輪轉速改變。
39. 身為讀者，我想切換狀態時零件以短動畫移到新位置，這樣我看得出是哪個零件改變了。
40. 身為讀者，我想按鈕標示目前選中的狀態，這樣我知道模型現在處於哪一種配置。
41. 身為讀者，我想切換狀態時機構繼續照播放 / 暫停的設定運作，這樣能直接看到切換後的效果。
42. 身為讀者，我想沒有狀態可切換的模型不出現狀態按鈕，這樣畫面保持乾淨。

### 讀數與標籤

43. 身為讀者，我想在滑輪組模型（第 12–22 種）角落看到「繩端拉了多少、重物升了多少、省力比」，這樣能直接驗證原文的比例（例如第 15 種 1:7）。
44. 身為讀者，我想這些數字隨我拖動即時更新，這樣我能看到位移比固定不變。
45. 身為讀者，我想看到原文提到的字母（如第 5 種張緊輪 B、第 23 種皮帶輪 A、導引輪 B、配重 C）浮在對應零件旁，這樣讀說明時能對上。
46. 身為讀者，我想字母標籤跟著零件和視角移動，並且一直朝向我，這樣任何角度都讀得到。
47. 身為讀者，我想原文沒有字母的模型不出現標籤，這樣不會出現原書沒有的符號。

### 外觀與可靠性

48. 身為讀者，我想模型是白底、黑色輪廓線、淡灰陰影的線稿風，這樣它跟旁邊的版畫插圖是同一種味道。
49. 身為讀者，我想皮帶看得出在移動（例如上面有間隔記號），這樣能判斷皮帶的走向。
50. 身為讀者，我想模型在手機和桌機上都能流暢操作，這樣到哪裡都能用。
51. 身為讀者，我想不切到模型時不必下載 3D 函式庫，這樣只想讀文字時網頁開啟速度不受影響。
52. 身為讀者，我想 3D 函式庫載入失敗時看到簡短提示、插圖和文字照常可看，這樣網路不穩時仍能閱讀。
53. 身為讀者，我想切換插圖 / 模型時不會閃白或整張卡片跳動，這樣閱讀不被打斷。

### 維護者

54. 身為維護者，我想每個模型的運動學定義和 3D 繪圖分開，這樣我能不開瀏覽器就驗證一個模型的動作是否符合原文。
55. 身為維護者，我想新增一張插圖的模型只需要寫一份模型定義並登記圖號，這樣日後可以逐章擴充。
56. 身為維護者，我想模型以圖號對應插圖，這樣條目的分合（如「19–22」共用文字）不影響模型。
57. 身為維護者，我想每個模型的測試直接引用原文斷言（同向、反向、比例），這樣測試就是原文的可執行版本。
58. 身為維護者，我想不必引入任何套件就能跑測試，這樣專案維持零依賴。

## Implementation Decisions

### 架構

- **模型定義（運動學）與繪圖分離。** 每個模型是一份純資料加純函式的定義，不依賴 Three.js 或 DOM。繪圖層讀取定義來建立 3D 場景，每一幀把計算出的姿勢套用到場景上。這是唯一的測試切點。
- **模型定義的介面**（概念形狀，非最終程式碼）：
  - `figure`：圖號（數字），模型以此對應插圖。
  - `parts`：零件清單，每個零件有 id、種類（皮帶輪、軸、皮帶、繩、重物、槓桿、扇形段、齒輪等）、尺寸、在模型座標中的配置，以及選用的字母標籤。
  - `driver`：哪個零件是主動件、驅動量的種類（`rotation` 角度或 `translation` 位移），以及選用的範圍 `[min, max]`（繩端、槓桿需要；連續旋轉的輪子不設範圍）。
  - `states`（選用）：可切換的狀態清單（id + 按鈕文字）與預設狀態。
  - `pose(driverValue, stateId)`：純函式，回傳每個零件的姿勢（位置、旋轉）、每條皮帶或繩的行進相位（用來畫移動記號），以及讀數清單（標籤 + 數值，例如「省力比 1:7」）。
  - 選用的初始視角，讓模型一開始的角度接近原書插圖。
- **模型登記表**：以圖號為鍵，列出有模型的插圖。卡片用它判斷要不要顯示「插圖 / 模型」切換和圖號小頁籤。
- **運動學原則（ADR-0001）**：
  - 皮帶傳動以半徑比換算轉角；開口皮帶同向，交叉皮帶反向。
  - 空轉輪不傳動。
  - 張緊輪未壓下時，從動輪轉角固定不變。
  - 滑輪組以繩長守恆換算重物位移，省力比由位移比算出。
  - 不模擬力、質量、慣性或摩擦。
- **3D 函式庫**：Three.js，透過 CDN 以 ES module 載入並固定版本。網站部署於 GitHub Pages。第一次切到模型模式才載入（延遲載入）。
- **畫風**：白底、黑色粗輪廓線、淡灰平塗陰影。主動件用單一強調色。字母標籤以永遠面向鏡頭的文字呈現，跟著零件移動。

### 卡片行為（修改既有卡片）

- 頁面層級新增一個「圖片區模式」狀態（插圖 / 模型），預設是插圖，翻頁和切章都保留。目前卡片沒有模型時，畫面一律顯示插圖，但不清除這個模式狀態。
- 模型模式下，圖片區的「點左右半邊翻頁」和「觸控滑動翻頁」停用；上下張按鈕與鍵盤左右鍵、Esc 返回維持原樣。
- 多插圖條目在模型模式下顯示圖號小頁籤。只有有模型的插圖才出現在頁籤上，一次只建立一個 3D 場景。交互參照跳轉時，選中目標圖號的頁籤。
- 整頁共用同一個 3D 繪圖畫布，換卡片時重建場景、釋放舊場景的資源，避免手機上 WebGL context 不斷累積。
- 沿用既有的「組好再換上、避免閃白」原則：模型場景準備好才換上圖片區。

### 互動規則

- 指標按下時用射線判斷是否點中主動件：點中就進入「拖動主動件」，沒點中就是「轉視角」。滾輪和雙指捏合用來縮放。另外提供重設視角的方法。
- 旋轉型主動件：以指標相對於軸心在螢幕上的角度變化作為轉角增量。位移型主動件：以指標沿繩方向的投影作為位移增量，並夾在範圍內。
- 播放：進入模型時自動以慢速播放。按下主動件立即暫停，放開後維持暫停。有播放 / 暫停按鈕與速度控制。有範圍的主動件在自動播放時於範圍內往復。
- 狀態切換：模型下方的按鈕列；切換時相關零件以短動畫過渡到新位置，播放狀態不變。
- 讀數：只有定義中回傳讀數的模型（第一章為滑輪組 12–22）才在模型角落顯示。

### 試點範圍內容

- 第一章「皮帶與滑輪」圖 1–23，共 23 個模型。有狀態切換的至少包括第 2、5、7、8、9、10 種；有讀數的為第 12–22 種；有字母標籤的依原文（如第 5、7、23 種）。

## Testing Decisions

- **好的測試只驗外部行為**：呼叫模型定義的 `pose(driverValue, stateId)`，斷言回傳的姿勢與讀數符合原文描述。不檢查內部計算步驟，也不碰 Three.js 場景。
- **唯一的測試切點是模型定義**。用 Node 內建的測試執行器跑，不安裝任何套件。模型定義必須是可同時被瀏覽器與 Node 載入的 ES module。
- **測試案例直接對應原文**，例如：
  - 第 1 種：主動輪轉 +θ，從動輪同向轉 θ·r主/r從。
  - 第 2 種：交叉皮帶狀態下從動輪反向；切換固定輪上的皮帶後，從動軸反轉，主動端方向不變。
  - 第 5 種：張緊輪「放開」狀態下，不論主動輪怎麼轉，從動輪轉角都不變；「壓下」時才傳動。
  - 第 7 種：中輪時直立軸不轉，左輪與右輪時轉向相反。
  - 第 8–10 種：不同皮帶位置下從動輪轉速比不同，而且符合半徑比。
  - 第 12 種：施力端位移等於重物位移（1:1）。第 13 種：繩端位移是重物的兩倍。第 15 種：省力比 1:7。第 19–22 種：省力比為 2 的可動輪數量次方。
  - 有範圍的主動件：超出範圍的輸入會被夾住。
- **登記表的完整性測試**：第一章 23 個圖號都有模型；每個模型的主動件指向存在的零件；有狀態的模型，其預設狀態在狀態清單中。
- **不寫自動測試的部分**：卡片切換、模式記憶、手勢分流、小頁籤、延遲載入、CDN 失敗提示。這些以手動驗證清單在 GitHub Pages 上確認（桌機與手機各一次）。
- **既有範例**：專案目前沒有任何測試，這是第一組。

## Out of Scope

- 第一章以外的章節的模型（之後以章節為單位擴充）。
- 獨立的模型頁面，包括多模型並排比較、整章一覽、自由組裝沙盒。
- 物理碰撞、重力、慣性、摩擦、力的模擬（ADR-0001）。
- 參數調整（改齒數、半徑、連桿長度）。
- 在 3D 中直接拖動非主動件來切換狀態（狀態切換只用按鈕）。
- 離線使用模型；用 file:// 直接開啟時的模型支援（插圖與文字仍可）。
- 卡片切換與手勢的瀏覽器端自動測試。
- 皮帶輪轉速（rpm）讀數；第一章只有滑輪組顯示讀數。

## Further Notes

- 用語遵循 CONTEXT.md：插圖、模型、主動件、條目、卡片、章節、頁籤。避免使用「物理模型 / 模擬器 / 動畫 / 輸入件」。
- 模型定義改用 ES module 後，本機預覽需要靜態伺服器（例如 VS Code Live Server）。直接雙擊 index.html 時，插圖與文字仍應正常，只是模型無法載入。
- 第 3、4、11 種是兩軸成直角的空間配置，初始視角要選能同時看清兩軸的斜視角度。
- 第 23 種有配重與導引輪，其中「框架在導軌間滑動」原圖未繪出，模型可以簡化成只畫可見零件。
- 原文的「第 N 種」交互參照是以圖號解析的，這和「模型以圖號對應」一致。
