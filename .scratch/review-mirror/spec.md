# 審閱鏡像:待決事項放頁首、參考資料放後半、可點連結跳轉

Status: ready-for-agent

## Problem Statement

要我核可的 md(審核關卡)會另外發布成 artifact 鏡像給我看。鏡像現在照正本的順序逐字排版,「需要你決定的」只是其中一節,夾在長篇的進度說明與表格之間(以 pending.md 為例,它在第 6 節,前面是「完成到什麼程度」「這一輪改了什麼」「第三輪」,後面是 42 列的待確認表格)。結果是:

- **找不到要決定的事**:打開頁面看不出這次要我做什麼決定,得從頭讀到中段才遇到。
- **待決和已決混在一起**:pending.md 的「需要你決定的」裡,真正待決的只有兩項(動力重演要不要繼續、未修剩下的 3 張),其餘三項(第 353 種、第 87/186/187 種、第 70/71/462 種)早已決定,但寫法一樣;另一節「這一輪新增、需要確認的判定」其實也是決策,卻不在決策段裡。
- **決策要的背景要自己找**:一個問題提到「動力重演」「第 185、422、483 種」,相關說明散在後面的章節與長表格裡,只能自己捲動去找,看完再捲回來。
- **每次排版不一樣**:鏡像的渲染程式每次發布時臨時重寫,目前只支援標題、清單、表格、粗體、行內程式碼,沒有連結。

## Solution

審閱鏡像改成「決策在上、參考在下」的頁面,並把產生鏡像的流程固定成一個 skill。

- 頁面最上方是**決策區**:先列待決事項(問題、選項、我的建議),已決事項排在區塊後段、只顯示一行灰掉的問題,點開才看到決定內容。沒有待決事項時明白寫出「沒有待決事項,只需核可整份」。
- 正本其餘各節照原順序排在後半,當**參考資料**。
- 問題裡的詞可以是連結,點了直接捲到後半的某一節或某張表格的某一列並高亮;看完可以用浮動的「回到剛才的問題」按鈕回到原處,或用各節標題旁的「↑ 決策」回到決策區開頭。
- 正本仍是唯一來源:決策段在正本裡照固定格式寫,鏡像由固定腳本機械地抽出、排序、加連結。鏡像的內容與正本逐字一致,只有決策段的位置不同。
- pending.md 這次就改成新格式並重新發布,沿用原本的網址。

## User Stories

1. 身為審閱者,我想一打開鏡像就看到這次要我決定的事,這樣我不用讀完整份才知道要做什麼。
2. 身為審閱者,我想待決事項排在已決事項前面,這樣我的注意力先落在還沒處理的事上。
3. 身為審閱者,我想已決事項只佔一行並灰掉,這樣它們不會擠掉待決事項。
4. 身為審閱者,我想點開已決事項就看到當時的決定與選項,這樣我可以回頭查為什麼這樣決定。
5. 身為審閱者,我想每個待決事項都寫成一個問題,加上幾個具體選項、各自的代價、以及標明的建議,這樣我回覆時只要說選哪一個。
6. 身為審閱者,我想在沒有待決事項時看到「沒有待決事項,只需核可整份」,這樣我不會以為漏了什麼。
7. 身為審閱者,我想問題裡提到的術語、章節、圖號是可以點的連結,這樣我不用自己捲動去找背景資料。
8. 身為審閱者,我想點到表格某一列的連結時,頁面直接捲到那一列並高亮,這樣 42 列的長表格裡我不用自己找。
9. 身為審閱者,我想連結指向的值在表格裡有好幾列時(例如第 483 種有兩列、第 87 種有三列),所有同值的列都高亮、捲到第一列,這樣我不會只看到其中一列。
10. 身為審閱者,我想看完參考資料後按一個浮動按鈕就回到剛才那個問題,這樣我不會在長頁面裡迷路。
11. 身為審閱者,我想浮動按鈕上寫出要回到哪個問題,這樣我知道按下去會去哪裡。
12. 身為審閱者,我想參考區每一節的標題旁都有回到決策區的連結,這樣我自己捲下去瀏覽時也回得去。
13. 身為審閱者,我想點連結不會改變網址、不依賴瀏覽器的上一頁,這樣在 claude.ai 的內嵌框裡不會意外離開 artifact。
14. 身為審閱者,我想參考資料照正本原本的順序排列,這樣我和正本對照時不會錯亂。
15. 身為審閱者,我想鏡像的內容和正本逐字一致,這樣我在網頁上核可的就是檔案裡的內容。
16. 身為審閱者,我想鏡像在手機寬度也能讀、表格各自橫向捲動,這樣我在手機上也能審。
17. 身為審閱者,我想鏡像跟著系統的深色模式切換,這樣晚上看不刺眼。
18. 身為審閱者,我想鏡像頂端標明正本的檔名、說明審閱意見在對話中回覆,這樣我知道這頁是哪份檔案、怎麼回應。
19. 身為審閱者,我想每份審核關卡的 md 都用同樣的版面,這樣我不用每份重新適應。
20. 身為審閱者,我想 pending.md 這次就改成新格式,這樣我現在就能找到動力重演與未修 3 張這兩個待決事項。
21. 身為審閱者,我想 pending.md「這一輪新增、需要確認的判定」併入決策區成為一個已決事項,條文留在參考區、從問題連過去,這樣所有決策都在同一處。
22. 身為審閱者,我想更新後的 pending.md 鏡像沿用原本的網址,這樣我手上的連結不會失效。
23. 身為寫正本的代理,我想決策段有固定的寫法(固定標題、每項一個小標題、選項清單、決定行),這樣腳本能機械地認出待決與已決,不用人工排序。
24. 身為寫正本的代理,我想事項決定後只要加一行「決定(日期):…」,這樣不用搬動段落,鏡像自己會把它排到後段。
25. 身為寫正本的代理,我想連結目標用標題第一個括號之前的文字當錨點,這樣標題裡的數字(例如「(4 項,3 張)」)改了,連結不會斷。
26. 身為寫正本的代理,我想用「標題/第一欄的值」指定表格的某一列,這樣不用在正本裡另外放錨點語法。
27. 身為寫正本的代理,我想正本在 VS Code 的 md 預覽裡照樣讀得懂(連結是標準 md 寫法),這樣不開鏡像也能讀。
28. 身為發布鏡像的代理,我想用一支固定的腳本產生鏡像,這樣每次的排版與行為都一樣,不用臨時重寫。
29. 身為發布鏡像的代理,我想腳本在發布前檢查每個連結都找得到目標,找不到就報錯、不產生頁面,這樣審閱者不會點到壞連結。
30. 身為發布鏡像的代理,我想腳本在決策段格式不對時(例如有選項卻沒有小標題)報錯,這樣格式錯誤不會默默變成排版錯誤。
31. 身為發布鏡像的代理,我想 skill 說明裡寫清楚查 mirrors.json、沿用或新建 artifact、寫回對應的步驟,這樣發布流程不用每次重新推敲。
32. 身為發布鏡像的代理,我想 skill 附一份互動的手動驗證清單,這樣第一次發布時有依據可以請審閱者點過一遍。
33. 身為維護全域規則的人,我想全域 CLAUDE.md 的鏡像規則縮短成指向這個 skill,這樣每個專案載入的規則不會變長,細節只在要用時載入。
34. 身為維護全域規則的人,我想完成條件改成「內容逐字一致,只有決策段移到頁首」,這樣規則與新版面不衝突。
35. 身為維護全域規則的人,我想 skill 是使用者層級的、所有專案共用,這樣其他專案的審核關卡也用同一套。

## Implementation Decisions

- **使用者層級的 skill**(所有專案共用),名為 review-mirror。內容:正本決策段的寫法、發布步驟(含 mirrors.json 的查詢與寫回)、互動的手動驗證清單,以及一支固定的 Node 腳本。
- **全域 CLAUDE.md 的「審閱 md → 附 artifact 鏡像」改寫**:保留「何時要鏡像」(md 成為審核關卡、agent 文件除外)、「md 是正本、網址只記在 mirrors.json」、完成條件;怎麼寫、怎麼產生、怎麼發布改成「用 review-mirror skill」。完成條件的「鏡像與正本逐字一致」改為「內容逐字一致,只有決策段移到頁首」。
- **正本的決策段格式**:
  - 標題固定為 `## 需要你決定的`;一份正本最多一個。沒有這一節的正本,頁首決策區顯示「沒有待決事項,只需核可整份」(由腳本產生,正本不必寫)。
  - 每個事項是一個 `###` 小標題,小標題就是問題本身。
  - 小標題底下是選項清單,建議的選項標「(建議)」,每個選項寫出代價;選項前後可以有說明段落。
  - 決定後在事項裡加一行以「決定(日期):」開頭的文字。有這一行的就是已決。
  - 正本裡事項的順序由寫的人自由;鏡像把待決排前、已決排後,同一組內保持正本順序。
- **連結與錨點**:
  - 連結用標準 md 寫法 `[文字](#目標)`。
  - 節的錨點是標題文字到第一個「(」或「(」為止(去掉前後空白);沒有括號就是整個標題。
  - 表格列的錨點是「節的錨點/該列第一欄的值」;同值的列共用一個目標,跳轉時捲到第一列、高亮所有同值的列。
  - 錨點重名(兩個標題去掉括號後相同)視為錯誤。
- **腳本的入口**:一個函式,輸入正本的 md 文字與正本的顯示路徑,輸出頁面 HTML,或一份錯誤清單(斷連結、錨點重名、決策段格式錯誤)。有錯誤就不輸出頁面。命令列包一層:讀檔、呼叫入口、寫出 HTML 或印出錯誤並以非零結束。
- **頁面的組成**:
  - 正本原文以 JSON 字串嵌入頁面,由頁面上的渲染程式渲染(延續現行規則);版面只動 CSS。
  - 支援的 md:一到三級標題、段落、清單(含續行)、表格、粗體、行內程式碼、連結。
  - 頁首是決策區;其後是正本其餘各節,依原順序。
  - 已決事項以 HTML 的可展開元素呈現:收合時一行灰色的問題,展開後是事項的完整原文。
- **跳轉行為**:點內部連結時由程式捲動並高亮目標,不改網址、不寫入瀏覽器歷史;記住點連結的那個問題(只記最近一次),右下角浮出「↑ 回到:<問題>」按鈕,按下捲回該問題後隱藏。參考區每個二級標題旁加「↑ 決策」連結,回到決策區開頭。
- **頁面外觀**:沿用現行鏡像的單欄閱讀版面、色彩變數與深色模式、表格各自橫向捲動、手機寬度不出現整頁橫向捲動;頁首標明正本路徑與「審閱意見請在對話中回覆」。
- **pending.md 遷移**(同一批工作):
  - 決策段改寫成新格式。待決:「動力重演要不要繼續」(選項 a/b/c 照原文,另標建議)、「未修剩下的 3 張要不要補」。已決:第 353 種、第 87/186/187 種、第 70/71/462 種、「這一輪新增的 5 條判定要不要保留」。
  - 「這一輪新增、需要確認的判定」一節的條文保留在參考區(節名可調整成不含「需要確認」的說法),決策段的已決事項連過去。
  - 待決事項的問題裡加連結,指向「動力重演:做了什麼、為什麼沒做完」「未修清單」各列等。
  - 用新 skill 重新發布到 mirrors.json 記錄的同一個網址。
- 不新增專案 CONTEXT.md 的術語:審核關卡、正本、鏡像、決策段是使用者的工作流程用語,定義留在全域 CLAUDE.md 與 skill 裡。

## Testing Decisions

- **只有一個切入點**:腳本的入口函式(md 文字 → 頁面 HTML 或錯誤清單)。測試只看它的對外行為,不測內部的切塊或渲染細節。
- 測試放在 skill 目錄,用 Node 內建的測試執行器、零依賴(和本專案 `npm test` 同一套做法)。
- 要涵蓋的行為:
  - 決策區出現在參考資料之前;待決在前、已決在後,同組內保持正本順序。
  - 已決事項是收合的,但展開內容包含它的完整原文。
  - 沒有決策段時,決策區顯示「沒有待決事項,只需核可整份」。
  - 正本的每一段文字都出現在頁面嵌入的原文裡(逐字一致)。
  - 節錨點去掉括號部分;標題數字改變時連結仍有效。
  - 表格列錨點存在;第一欄重複時多列共用同一目標。
  - 斷連結、錨點重名、決策段格式錯誤時回傳錯誤清單、不輸出頁面。
- 頁面上的互動(捲動與高亮、浮動返回按鈕、「↑ 決策」、展開已決事項、深色模式、手機寬度)不做自動測試,改由 skill 裡的手動驗證清單;第一次用新 skill 發布 pending.md 時請審閱者在 claude.ai 上點過一遍。
- 前例:本專案以 Node 內建測試執行器測純函式的輸出(模型定義的 `pose()`),斷言對應明確的預期;這裡同樣只斷言入口函式的輸出。

## Out of Scope

- 在鏡像頁面上直接作答或留言(審閱仍在對話中進行,鏡像是純閱讀頁)。
- agent 文件(CLAUDE.md、SKILL.md、memory 等)的鏡像,維持不做。
- 回頭轉換其他既有的審閱 md(例如 physical-verification 的 spec、tickets);之後成為審核關卡時再照新格式寫。
- 支援上述以外的 md 語法(圖片、程式碼區塊、巢狀清單、引用)。
- 跨檔案的連結(只做同一份正本內的跳轉)。
- 把待決事項的回覆自動寫回正本。

## Further Notes

- 瀏覽器的「上一頁」在 claude.ai 內嵌框裡的行為不確定(可能退出 artifact),所以跳轉不改網址、由頁面自己的按鈕返回。
- 規格本身是審核關卡,這一份的鏡像仍用現行規則產生(新 skill 還沒有)。
