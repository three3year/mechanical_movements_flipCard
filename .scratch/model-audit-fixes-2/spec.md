## Problem Statement

第 251–300 種的模型實體驗證(50 張、0 個未豁免)與測試都通過,但掃描查出 98 筆維護者看網頁會退回的問題:

- 零件的各塊不相連、樞軸沒有銷、支架浮在底座上、主動件本身懸空(第 3 類「一件」最多,一件掃描在這段報出的幾乎都找不到實物理由)。
- 說「壓」「夾」「推」「靠在」的一對零件其實沒碰到,或整個穿進去:第 251 種楔形槽從沒壓到右鉗臂、第 253 種鉤尖穿進凸柱、第 269 種齒條的齒整個穿進停住的齒輪、第 280 種夾爪浮著、輪緣其實沒被夾。
- 豁免的原因寫錯,蓋住了真的問題(第 253、254、261、269、275、278 種)。
- 和原文或原圖不合:第 275 種齒條走的方向和螺紋相反、第 292 種前後叉瓦對調、第 262–263 種錐體走反、第 268 種滾子轉反、第 298 種整張圖讀錯(其實是惠更斯的 pirouette)、第 278 種的肘形槓桿做成直連桿。
- 外在缺了:擒縱模型沒有擺、擺輪與擒縱輪的驅動;調速器沒有驅動與被調節的對象(第 274、287 種);第 271 種的滑輪沒有繩與重物。
- 讀者看不出來:擒縱的關鍵接觸被前面的零件蓋住、初始視角太遠、轉向箭頭被擋或關掉、扁皮帶畫成細圓管。
- 中譯四處:第 262–263 種斷句錯、第 283 種 racks 是複數、第 284 種 carriage、第 288–289 種「擒縱瓦」不合術語表。

## Solution

照五份報告的建議修法與維護者 2026-10-12 的決定,把 98 筆問題修掉;修不了的照實寫成豁免、原因以「未修:」開頭並列進待確認清單。修完每一筆在報告裡加「狀態:已修(日期):做了什麼」,重新發布報告的鏡像。

跨圖共用的改動先做(路徑零件的扁帶畫法、錐體滾子模組、圓筒擒縱模組),再修各圖自己的問題。擒縱各圖補擺、擺輪與重錘驅動,沿用第 234、238 種的 `weightDrive`。

## Implementation Decisions

- **範圍**:五份報告裡第 251–300 種的 98 筆問題(第 12 族 9、第 13 族 30、第 14 族 32、第 15 族 19、第 16 族 8;第 16 族的 #297-1 和第 15 族的 #294-4 是同一件事分記兩族),照各筆的建議修法;有決定的照決定。報告裡「同類要一起查」指到範圍外的圖,不納入。
- **維護者的決定(2026-10-12,記在各報告)**:第 255、256 種加扁帶畫法(只用在這兩張);第 262–263 種錐體照原圖反過來走;第 265 種做斜的輸出軸、撥叉照主動量走;第 261 種鼓輪移到圓盤背面;第 267 種四條細直線是輪緣的輻條、臂維持鏡像;第 271 種照原圖補滑輪的繩與重物;第 278 種照原圖重做肘形槓桿;第 276 種做一根直桿;第 274 種補驅動與被調節的對象;第 284 種照原圖改進料螺絲;第 283 種照原圖做 U 形齒條;第 285 種只改註解;擒縱模型補擺與擺輪;第 294–300 種用 `weightDrive` 補重錘;第 298 種照原圖重讀成 pirouette(推翻舊定案);第 247 種的樞軸偏右與肘保留。第 11 族:第 234、238 種重錘捲回維持現狀;第 239 種擋爪維持靠彈簧。
- **先做共用的改動**:
  - 路徑零件的扁帶畫法(第 255、256 種):`belt` 加寬度選項,有寬度時畫成矩形斷面,實體驗證的碰撞體也改成扁盒;其他用 `belt` 的圖不設寬度、不受影響。
  - `cone-roller.js`(第 262、263 種)、`cylinder-escapement.js`(第 294、295 種)、`twin-wheel-escapement.js`(第 300 種,第 301 種也用它):改共用模組時確認同模組的其他圖不壞。
  - 重錘驅動沿用 `models/weight-drive.js`,不另寫。
- **推斷的零件**:補上的擺、擺輪、重錘、滑輪、繩、機架、軸承、導套、閥桿等,一律在模型註解標明是推斷;偏離插圖的地方寫明理由(照「原文 > 實物可行 > 插圖外形」)。
- **由接觸算**:改成接觸的地方用現有的接觸工具(外形放置、重疊判斷、沿弧擺到相碰、推到不重疊),不手寫時間窗。

## Testing Decisions

- **接縫**:沿用現有的兩個——模型定義(`npm test`,對各圖匯出的 pose() 與接觸函式下斷言)與實體驗證(`npm run verify`)。不新增接縫;截圖對照照 `docs/agents/model-audit.md` 的做法手動做。
- **好的斷言**:對到原文的一句(例:「槽的兩側把鉗臂上端往內推」「齒條沿螺紋的方向前進」),或對到接觸(相碰的一對間隙接近 0、少轉一點就穿入、全程不穿入)。不要只數零件的塊數或重複模型自己的公式。這次掃描抓到兩個測試只量轉角、沒量外形就漏掉穿入的例子(第 253 種鉤尖、第 262 種立桿),改成量實際外形。
- **每筆先寫失敗的測試再改模型**(TDD),能用斷言表達的都要有斷言;純外觀的(箭頭位置、字母、顏色、取景)以截圖確認並寫進報告。
- **前例**:第 234、238 種的重錘驅動測試(繩長不變、繩繞在鼓上、重錘拉力讓輪往前轉、輪停重錘停);第 247 種「錘靠在托腳上,再低一點就穿入」;第 239 種「再轉 0.01 就撞進端面」;擒縱各圖的全程不穿入檢查。
- **每張票的完成條件**:該範圍 `npm run verify -- 圖號…` 通過、`npm test` 全過、`node tools/rigid-links.mjs` 與 `node tools/one-piece.mjs` 在該範圍不再報出已修的問題(剩下的每一項寫出理由)、每張改過的圖截四個相位(含斜後方)對照原圖。最後一張票跑全書 `npm run verify`。
