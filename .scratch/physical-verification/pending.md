## 這一輪新增的判定

第一輪的規則不變。這一輪為了少寫內容相同的豁免,多了下面幾條;不同意的話告訴我,我改回逐張豁免。(維護者 2026-10-04:先維持目前的樣子。)

- **螺桿的螺紋轉在沒畫出來的螺孔裡不算干涉。** 螺紋和螺桿的芯一樣當成軸:它的軸線在對方座標裡始終是同一條(螺帽沿螺桿滑、螺桿在軸承座裡轉)才算,而且螺紋要整根穿過對方(兩端都露在外面;只從旁邊蹭到、或端頭停在對方裡面的仍照報,後者逐張寫豁免)。蝸桿對蝸輪不適用(蝸輪轉動時蝸桿的軸線在它的座標裡會移動),仍照報。
- **長條方桿沿自己的長軸在導座裡滑動不算干涉。** 長度至少是寬、厚三倍的方塊,軸線在對方座標裡始終是同一條、而且整根穿過對方(兩端都露在外面)才算(在沒畫出方孔的導座裡滑動的桿);一頭頂進實心零件、只從旁邊蹭到的仍照報;橫著掃過別的零件、或繞樞軸擺動的桿仍照報。
- **動力重演的豁免可以用 `at` 指明是哪一個預期事件**(主動量),只放過那一個;沒寫 `at` 就是該零件的每個預期事件(處理第一輪 code review 留下的第一項)。
- **`powered`(外力來源)用在幾個不是虛擬主動件的模型上**:第 379 種的進給螺桿(由操作的人另外轉動)、第 466、467 種被水頂起的柱塞 / 圓筒(液壓傳動)、第 471、472 種被空氣墊 / 壓縮空氣帶動的錘。另有第 218 種(梳毛機,`models/wool-comb.js`)的槓桿:帶動它的凸輪沒有畫出來。這些零件和主動件之間本來就沒有實體相連(或相連的零件沒畫)。

## 動力重演:做了什麼、為什麼沒做完

- **修了一個工具的 bug**:動力重演的 `ignore`(以及樞軸兩端的零件互不碰撞)從來沒有生效過——物理引擎要傳事件佇列才會呼叫過濾函式。已修正並補測試。第 63 種當初的重演結果是在這個 bug 之下得到的,它的豁免還沒有重新檢討。
- **補了 3 張並通過**:第 72、154、353 種(都是已改成由接觸算姿勢的模型)。第 353 種的重演查出砧面沒有對到錘頭落下的位置(錘頭其實懸在半空),已修。
- **棘輪一族(第 49、75–83 種)試過,全部不過,宣告已撤回**。原因是模型本身:棘爪是照時序擺放的,不是靠自重或彈簧搭在齒上;把棘爪也宣告成自由零件後(第 77 種),棘爪根本碰不到輪上的凸柱(前後層不同、鉤形沒畫到),直接垂下去。也就是說,要通過得逐張把「演出的接觸」改成真的接觸幾何,不是補一段宣告就好。
- **因此其餘名單沒有補**。以這一輪的速度估計,每張要重做接觸幾何加調整宣告,約 100 張;這是另一輪規模的工作,需要你決定要不要做、先做哪幾族(見「需要你決定的」)。
- 補宣告的成本:每張重演約 5–10 秒,全書都補的話 `npm run verify` 會從 1 分鐘左右變成十幾分鐘。

## code review 留下、還沒處理的

- 沒有 `replay` 宣告的模型無法寫動力重演的豁免(會被報成過時)。
- 動力重演只比各預期事件當下的轉角與位置,沒有另外檢查先後順序;`replay.ignore`、`seconds`、`tolerance` 不要求寫原因。
- 線狀零件對任何實體都以中心線算穿入(規格只說纏繞或掛著的輪相貼不算);線狀零件彼此之間不查干涉。
- `lathe`(旋轉體)零件的 `pieces` 繪圖層不會畫出來(第 457–459 種的水桶提把原本因此沒畫出來,已改成群組);其他用到的地方沒有逐一查。
- 取樣與預設速度的規則在 `verify/sampling.js` 與 `viewer/viewer.js` 各有一份(未抽成共用)。
- 提交仍然不是「每章一個提交」:這一輪依處理的批次提交,工具規則的調整夾在查修的提交裡。
