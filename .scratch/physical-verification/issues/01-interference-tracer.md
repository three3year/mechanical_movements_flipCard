# 01 — 干涉的第一條通路

**What to build:** 維護者用一個獨立指令,對指定圖號的模型跑實體驗證的第一項——干涉——並看到報告。實體驗證只有一個入口:給一份模型定義,回傳一份問題清單。零件的 3D 形狀與姿勢的擺放沿用繪圖層的建構方式(驗的就是讀者看到的形狀),因此先做前置整理,讓繪圖層的零件建構與擺放能在沒有瀏覽器的環境被引用。物理引擎與 Three.js 裝成開發用依賴;網站與既有的測試指令不變。這一張先涵蓋板、圓柱、方塊、群組(含附屬小零件)等剛體零件,不限軸向。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

規格:`.scratch/physical-verification/spec.md`;用語見 `CONTEXT.md`(實體驗證、干涉、憑空連動、動力重演、豁免);相關決定見 ADR-0001、ADR-0003。

- [ ] 物理引擎(Rapier 的 Node 版)與 Three.js(與網站 CDN 同一版)裝成開發用依賴;網站載入的內容不變
- [ ] 既有的測試指令仍然零依賴、全部通過,且不會收進實體驗證的測試
- [ ] 有一個獨立指令執行實體驗證的測試;另可對指定圖號執行並印出報告
- [ ] 繪圖層的零件建構與姿勢擺放可在 Node 引用(不碰 DOM),網站上的畫面與行為不變
- [ ] 實體驗證的入口是「模型定義(加選項)→ 問題清單」;每個問題含檢查種類、圖號、涉及的零件、主動量、狀態、穿入深度、發生次數、文字說明
- [ ] 沿用自動播放的取樣方式,在主動件的行程上取樣姿勢
- [ ] 合成模型測試(成對,一錯一對):兩塊板同平面重疊 / 錯開;圓柱穿過方塊 / 穿過方塊上的孔;不同軸向的兩個零件相交 / 不相交;只在某個主動量才撞上的兩個零件會被報出,且回報的主動量落在那一段
- [ ] 穿入深度小於容許值的不報;同一個零件自己的各部分之間不查
- [ ] 同一份定義跑兩次,問題清單完全相同
- [ ] 對一張真實的模型跑得出報告
